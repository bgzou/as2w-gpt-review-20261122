# 03 数据模式与有效性规则

- 日期:2026-11-19
- 覆盖:任务书 §3.3(真机数据字段)、§5.1–5.2(合同表/主矩阵)、§6.4(离线测试)

## 1. 每次会话的文件组成(七件套 + manifest)

| 文件 | 产生者 | 频率 | 内容 |
|---|---|---|---|
| `session.log` | 会话脚本 | 事件 | step1–6 门检结论、控制权切换、时间戳、SHA 记录 |
| `low_capture_fast.log` | `as2w_sdk2 low-capture eth0 rt/lowstate <sec> 2` | **500 Hz** | LOW_SAMPLE:elapsed_ms,packet_count,age_ms,tick,mode_pr,mode_machine,quat×4,gyro×3,35 槽×(q,dq,ddq,tau_est,mode,temp) |
| `low_protection.log` | `as2w_sdk2 low-protection` | 5 ms 轮询 | PROTECT 行:motorstate/warning 保护位、主板状态、电压电流 |
| `lowcmd_capture.log` | `as2w_sdk2 lowcmd-capture`(O-G/O-S 会话) | 100 Hz(period 可设 2 ms) | LOWCMD_SAMPLE:elapsed,cmd/low 包计数与年龄,**low_tick(2026-11-19+ 构建,与 500 Hz 状态流按固件 tick 精确配对)**,mode_pr/mode_machine,逐帧 CRC,35 槽×(mode,q,dq,kp,kd,tau)+reserve;与主采集窗口**全程并发**(2026-11-19 对探针已验证并发采集链可用) |
| `debug_lowcmd.csv` | 发布端(仅 hipdiag 会话) | 500 Hz | DEBUG_LOWCMD:mono_ns,tick,state,mode_machine + 16 契约轴×(slot,mode,q,dq,kp,kd,tau) |
| `debug_policy.csv` | 发布端(--debug) | 500 Hz | 每帧命令上下文(含遥控原始轴) |
| `policy_diag.log` | 发布端(hipdiag) | 50 Hz | HIPDIAG_DIAG(见 §4) |
| `publisher.log` | 会话脚本 tee | — | 发布端控制台(含 FIELD_SAFETY/门检/退出码) |
| `experiment_manifest.csv` | 会话脚本生成表头,**现场填写** | 每会话一行 | 见 §2 |

O-G/O-S 官方会话无发布端:`session.log`、`lowcmd_capture.log`(只读采集:订阅 `rt/lowcmd`+并行 `rt/lowstate` 活性对照,逐帧 CRC,**0 包也如实记录**;2026-11-19 起与主窗口并发全程采集,官方命令-状态静差 e_q 按 low_tick 配对)、`low_capture_fast.log`、`low_protection.log`、`experiment_manifest.csv`(五件)。`debug_lowcmd.csv` 缺失原因=本项目发布端未运行(其自记录不存在);官方命令是否可见以 `lowcmd_capture.log` 探针结果为准(00 审计 §1.2):有包→cmd 字段=实测;0 包→cmd 字段 NULL,manifest `missing_fields_reason` 写"rt/lowcmd 探针 0 包(lowstate 正常)"。

## 2. experiment_manifest.csv(现场填写,每会话一行)

```
session_id,experiment_id,support_state,wheel_contact_front,wheel_contact_rear,
wheel_clearance_check,brace_photo_paths,brace_contact_other_parts,official_mode_fsm,
operator,consent_record,room_temp_c,robot_notes,stable_window_start_list,
stable_window_end_list,missing_fields_reason,anomalies
```

- `support_state`: `GROUND` / `SUPPORTED_SUSPENDED`
- `wheel_contact_front/rear`: 现场目视确认 `YES`/`NO`(P55-S/O-S 必须四轮 NO)
- `wheel_clearance_check`: 全扫角范围内轮/腿离地离支架间隙是否足够 `YES`/`NO`
- `official_mode_fsm`: O-G/O-S 时的 GetState fsm 名(如 `ai_stand_up`);hipdiag 会话填发布端状态名
- `consent_record`: 当次许可记录(谁、何时、范围)
- `stable_window_start_list/end_list`: 现场或 QC 后填的稳态窗口(秒,分号分隔,支持一窗/三窗)
- `anomalies`: 任何异常声音/跳动/支架移动/接触

## 3. 字段→任务书 §3.3 对照

| 任务书要求 | 落点 | 备注 |
|---|---|---|
| 实验编号/模式名/状态码/唯一 writer | manifest + session.log + LOW_SAMPLE.mode_machine + 16 轴 mode | 官方会话 16 轴 mode 应为 1(官方受控正常态)——**不适用** mode=0 writer 断言(该断言仅 hipdiag 启动门检) |
| 支撑状态/四轮接触/支架照片 | manifest(照片路径,照片单独存放不入会话目录) | |
| 16 轴原始 LowCmd/LowState | debug_lowcmd.csv(500 Hz)/LOW_SAMPLE(500 Hz) | 官方 cmd=NULL(§1) |
| cmd_q/dq/kp/kd/tau(官方不可见) | hipdiag:55/2/0 逐帧;官方:NULL | 禁止填默认假值 |
| st_q/dq/tau_est、温度、错误码 | LOW_SAMPLE 每轴 temp[0]、mode;保护位在 low_protection | ddq 亦采 |
| IMU 四元数/gyro/roll-pitch | LOW_SAMPLE quat+gyro(roll/pitch 由 quat 导出,QC 计算) | |
| 实际频率/缺帧 | LOW_SAMPLE.packet_count 单调性 + age_ms;debug_lowcmd dropped=0 断言 | |
| 启停/切换事件、SHA、软件版本 | session.log(step1 SHA 全表、控制权时间戳)、publisher.log | |

## 4. policy_diag.log — hipdiag 专用行(按 as2w_publish.cpp 实际输出,2026-11-19 核对)

```
HIPDIAG_DIAG_SCHEMA,phase,t_since_walk_s,tick,cmd_vx,cmd_vy,cmd_wz,axis_index,axis_name,plan_offset,plan_phase,target_q_0..11,target_dq_12..15
HIPDIAG_DIAG,<phase>,<t>,<tick>,<vx>,<vy>,<wz>,<axis>,<name>,<offset>,<plan_phase>,<q12>,<dq4>
```

- `phase` ∈ {HANDOFF, WALK, BRAKE}(发布端状态机段名);`tick` 为当帧 LowState 固件 tick(与 500 Hz 状态流同轴,精确回连);`cmd_vx/vy/wz` 为当帧速度命令(hipdiag 恒 0)。
- `axis_index/axis_name` = 被扫 Hip 的合同轴(joint_names 序,0–3);`plan_offset/plan_phase` = 计划 CSV 当 tick 的偏置与相位(`plan_phase` ∈ {hold, move, settle, final})。
- `target_q_0..11` 为 12 腿合同序目标(= T2 + 扫轴偏置),`target_dq_12..15` 为轮目标(恒 0)。
- 滞回曲线的"同角度正反向接近"保持点配对由 `plan_phase=settle/final` 段切分(任务书 §4),无需旧版 point_index 字段(已按代码实现删除)。

## 5. 有效性规则(QC 门,采集后立即由 `validate_session.py` 检查)

运行方式(脚本 `scripts/validate_session.py`,离线、无机器人访问):

```
python scripts/validate_session.py --mode og    --dir <会话目录>
python scripts/validate_session.py --mode p55g  --dir <会话目录>
python scripts/validate_session.py --mode sweep --dir <会话目录> --plan <该次扫角 plan.csv>
```

退出码 0=VALID、1=INVALID(任一 FAIL)、2=用法错误。工具按**实际生产端格式**解析七件套(含 2026-11-19 前/后两种 lowcmd schema,旧 schema 无 low_tick 时 e_q 配对降级为 lowstate 包计数近似并在结果中标注 APPROX)。2026-11-19 已用真机 O-G 对探针数据 + 合成 p55/sweep 干净与损坏会话完成正/负路径回归。任一失败 → 该会话标记 INVALID,不得用于对照,同实验须重采:

1. **完整性**:`low_capture_fast.log` LOW_SAMPLE 行数 ≥ 期望帧数×95%;`packet_count` 单调;`age_ms` P99 ≤ 5 ms;`debug_lowcmd.csv` 结尾 `dropped=0 file_ok=1`(hipdiag,结果行在 publisher.log/session.log);
2. **合同一致**(hipdiag):全发布窗口 16 契约轴 mode=1;腿 kp 恒 55、kd 恒 2、tau 恒 0;轮 kp=0/kd=2/dq=0。增益/T2 检查窗口:P55 格=FixedStand(state==2)行、扫角格=PolicyHandoff/PolicyWalk/Brake(state 3/4/5)行,T2 目标恒定只查 P55 的 FixedStand 行与扫角的 PolicyWalk 行(扫角=非扫 11 腿恒定);FixStand 进入段的渐变增益只报告不断言。`debug_lowcmd` 末帧 tick 与状态流**发布窗口内**末帧 tick 差 ≤ 10 ms(状态采集比发布端活得久,不与停发后行比较);
3. **合同一致**(O-G/O-S):官方站立窗口内 16 轴 mode=1、无保护位置位;cmd 字段按 `lowcmd_capture.log` 探针结果填(有包=逐帧实测+CRC 全过;0 包且并行 lowstate 正常=NULL 合法;lowstate 也 0 包=探针无效,重测);
4. **保护流**:`low_protection.log` 无 motorstate/warning 置位行(基线噪声除外:与既往干净会话同型);
5. **IMU/姿态**:悬空/地面会话各自记录 quat 导出 roll/pitch 均值±std 入 QC 表(分析按实际姿态重算重力,不强行对齐 −6°,任务书 §3.1);
6. **稳态窗口**:O-G/O-S/P55 每会话 ≥1(目标 3):滑动 10 s 窗口,窗口内每腿关节 |dq| P95 ≤ 0.15 rad/s,官方会话另查 mode_machine 恒定+16 轴 mode=1,P55 会话另查窗口落在 FixedStand 且目标恒定。HIP-SWEEP 的"窗口"= 计划 settle/final 保持段(≥0.9 s、偏置恒定,即滞回配对点),不由 10 s 滑窗定义;
7. **扫角计划**(HIP-SWEEP):policy_diag 偏置序列与计划 CSV 逐帧一致(≤1e-4 rad);单帧目标步进 ≤ 0.001 rad(max_velocity×dt);只动声明的那个 Hip(其他 11 轴目标恒定);|offset| ≤ yaml cap 0.02;轮 dq 目标恒 0。

QC 输出:`session_qc.csv`(每会话 × 16 DDS 轴:st_q/st_tau/e_q 的 mean/std/median/P5/P95/max_abs、dq P95、温度 mean;含窗口起止与配对方式)+ `qc_verdict.txt`(逐项 PASS/FAIL/WARN 与最终 VALID/INVALID)。e_q = 命令目标 − 实测位置(O-G/O-S 用 lowcmd 探针,hipdiag 用 debug_lowcmd;轮的 e_q 无位置意义仅存档)。

## 6. 明确的"不做"清单

- 不把官方会话伪装成有命令侧数据(无插值、无假设 cmd);
- 不用 PD 重建代替实测(重建 τ_PD 仅作一致性校验列,不做负载结论);
- 不因"误差变小/力矩变小"自动判定模型正确(分析纪律见 05);
- 分析(模式间对照、重力残差、滞回)不在采集阶段展开——按用户另行安排。
