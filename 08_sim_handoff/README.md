# 仿真同事交付包（2026-11-22）

这份包是"AS2-W 两条上机策略诊断"的**完整证据 + 给仿真侧的请求**。目标：让负责仿真/训练的同事（以及他用的 AI）能**不看别的材料**就明白问题、并知道下一步该怎么仿真。

## 一、两句话结论

1. **v2-step**（侧移/转向踏步线）上机后：站着抖（目标峰峰值 0.36 rad、翻转率 8–13%）、侧移/转向几乎不动（yaw 只跟 0.15–0.20）、右后轮**永远不会抬起**。根因在**训练目标与训练数据**：右移几何死结、门禁资格掩码让 7/16 组合不可得分、步态没有轮差速只能靠踏步、训练摩擦 0.5 是实机（≈0.25）的两倍。μ 对齐重训后转向反而更差（0.146 < 0.199）。
2. **HIMLoco**（腿轮联合）上机后：能站、能走，但推杆时**后腿被体重压下去 0.33 rad（下沉 3–4 cm）**；用"抬高目标"补偿导致前腿反向、前倾、嗡鸣。根因是**腿的 kp=55 余量不足**（静差 ≈ 重力矩/kp）+ **训练世界的载荷只有实机一半**（前髋力矩 3.7–5.1 vs 11–12 Nm）。**不是 kp/kd 抄错，也不是策略不会站。**

## 三、要仿真同事先做什么（按顺序）

1. **资产定案**：用整机称重判定 26.0 kg（官方 URDF）还是 27.512 kg（load-v0）；确认质心（x≈0.035 还是 0.020）。**27.012 kg 只是我们回填 base 的变体，不是实测。**
2. **接触模型校准**：按"任务清单 T2"跑 `impratio × condim × solref` 矩阵，记录 pitch / 四轮 Fn / 后腿 q / 前后髋力矩。**不要只调 μ**，也不要用"把某个力矩拟合上"来宣称接触模型已验证。
3. **有限接触斑候选**：只作结构敏感性（T3），不要宣称"证明根因"。
4. **横向力 Fy 方向**（T4）：实机侧待测，仿真侧先把"外撑 vs 内撑"两种情形的差别跑出来，供实机测量对照。
5. **kp A/B（仿真）**（T5）：55/2 vs 65/2 vs 85/3.2，零命令、同姿态，记录 `cmd−actual`/Fn/pitch。**这只是仿真；实机 A/B 另做。**
6. **修 MuJoCo 包装**（T6）：用 C++ 合同重建验收链，再谈"第二仿真器通过"。
7. **复跑 T3-3**（T7）：确认 0.13–0.38 rad 与四轮 Fn 分布（FL 34/FR 55/RL 65/RR 102 N），并解释左右不对称。
8. **门禁可满足性**（T8）：右移改 skating 后，仿真里能否稳定通过；三轮支撑窗口怎么统计。
9. **官方基准**（T9）：如果有官方 `ai_free_walk` 的参考数据，给出偏航响应的稳态与调节时间；没有就明确写"缺数据"。

## 四、必须遵守的约束

- **不要改正式 URDF/MJCF/USD**：所有实验在副本/candidate 上做，记录改了哪个文件、SHA、参数。
- **不要用旧的 MuJoCo Python 包装**：它与 C++/yaml 不一致（腿差 0.16 rad、轮差 10.9 rad/s）。统一用 60+ 帧夹具逐帧对齐。
- **区分引擎**：Isaac / PhysX / MuJoCo 的参数不能直接照抄（尤其摩擦参数与求解器阻抗）。
- **每个结论带来源与等级**：`CONFIRMED / OBSERVED / INFERRED / UNKNOWN`；每个数字给文件与字段。
- **不要跨策略借证据**：v2-step 的数字不能当 HIMLoco 的证据。
- **不要用仿真"通过"替代实机**：本轮所有仿真结论都只是"相对比较"，不是实机验收。

## 五、怎么和我们对齐

- 每个任务产出：配置/场景文件（含 SHA）、原始 JSON/CSV（不要只给截图）、一页结论（数字 + 等级 + 还缺什么）。
- 如果发现我们文档里的数字与原始数据冲突：**以原始数据为准**，并在回传里指出冲突位置。
- 需要新的实机测量（四轮 Fn、接触斑、Fy、12 轴方向）时，列成"需要现场做的测量"，不要用仿真值代替。
