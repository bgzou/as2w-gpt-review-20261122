# 给仿真同事的仿真任务清单（2026-11-22）

> 每条都给：目的、输入、做法、产出、判据、预计时间。**所有实验在 candidate/副本上做，不改正式资产；所有产出带 SHA 与原始数据。**
> 背景与结论见同目录 `01_RPT-016_根因分析.md`、`02_RPT-017_训练计划建议.md`。

## T1 资产定案：26.0 kg 还是 27.512 kg？

**目的**：训练资产的重量/质心必须唯一。现在有两套：官方 URDF（26.0 kg / base 10.08 / CoM x 0.035）与 load-v0（27.512 kg / base 11.592 / CoM x 0.020）。两者 base 差 1 kg、质心差 15 mm；我们实测过 base +1 kg 会让后腿静差 0.378→0.424 rad。

**输入**：`13_contracts_assets/urdf/as2w.urdf`、`as2w-load-v0.urdf`；现场称重结果（**需要现场提供**：整机总重、四轮分别 Fn、CoM）。

**做法**：
1. 准备两份 candidate 资产（不改正式文件）；
2. 按现场称重结果选一套；若总重落在 255 N 附近 → 官方；若 ≥270 N → load-v0；
3. 记录两套资产在**同一姿态、同一 kp** 下的 pitch / 四轮 Fn / 后腿 q。

**产出**：`asset_decision.json`（选哪套、依据、两套对比表）、两份资产副本的 SHA。

**判据**：总重与 CoM 能唯一对应一套资产；两套差异对后腿静差的影响有数字。

**时间**：0.5 天（不含现场称重）。

## T2 接触模型校准矩阵（重点）

**目的**：确定"仿真静态力矩像不像实机"到底由什么决定。已知：`impratio` 一阶（1→100 使前髋力矩 −4.61→−11.47 Nm），μ 0.8→1.0 只有 ≤0.3 Nm；但 W_A 与 W_D 由**互斥**的 impratio 主导，"双锚点不可兼得"。

**输入**：`10_sim2real_bundle/mujoco_abl/` 的 20 个场景、`tables/`、`11_phase_hij_audit` 的 I4/I5 结果、`13_contracts_assets/himloco/mujoco-scene_v2.xml`。

**做法**：
1. 固定资产（T1 结论）、固定姿态（实机 P55 站姿）、固定 kp55/kd2；
2. 扫 `impratio ∈ {1, 10, 100}` × `condim ∈ {3, 4, 6}` × `solref ∈ {默认, 软, 硬}`（先做 3×3×3 的粗网格）；
3. 每个配置记录：pitch、四轮 Fn、四 hip q、四 hip 力矩、接触点数；
4. 找出"能同时匹配 pitch + Fn + 后腿 q"的配置集合；对前髋力矩缺口单列，**不要为了拟合它去调 impratio**。

**产出**：`contact_matrix.json`（每配置一行）+ 一页结论：哪些指标可同时匹配、哪些不能、前髋缺口多大。

**判据**：pitch ≤0.3°、Fn ≤5%、后腿 q ≤0.07 rad 的配置存在；若不存在，明确写出"无单点配置可同时满足"，并给"哪些指标可信/哪些不可信"的声明。

**时间**：1–1.5 天（CPU 可跑）。

## T3 有限接触斑候选（只作结构敏感性）

**目的**：验证"点接触 vs 有限接触区域"是否在**结构上**改变平衡点；**不**用来宣称"证明实机根因"（缺实机接触斑数据）。

**做法**：
1. 刚性圆柱（现状） vs 胶囊/加宽接触 vs 柔性平面（`solref` 变软）；
2. 每个配置重复 T2 的三项指标；
3. 记录接触斑等效尺寸（若引擎能输出）。

**产出**：`contact_patch_sensitivity.json` + 一页结论（"能证明什么/不能证明什么"）。

**判据**：能量化"接触模型变化 → 力矩/姿态变化"的敏感度；不得写"根因已证实"。

**时间**：1 天。

## T4 横向力 Fy 方向：外撑还是内撑？

**目的**：实机地面 hip 力矩需要的侧向力方向是"外撑"（反演前 +24.1/−24.2、后 +18.6/−18.5 N），而 PhysX 给的是"向内"（−21.9/−19.7 N）。**方向是判别"接触几何错"还是"求解器错"的关键。**

**做法**：
1. 仿真侧：构造"单侧垫高 2–5 mm / 单轮侧向拉 20 N"的准静态场景，看四轮 Fy 的方向与量级；
2. 输出每种情形的 Fy 符号表；
3. 等实机侧做"单轮垫高/侧向拉拽/斜坡"后对照。

**产出**：`fy_direction_sim.json` + 对照表（仿真 vs 实机；实机列先留 `UNKNOWN`）。

**判据**：能给"外撑/内撑"两种假设各自的仿真特征；实机数据到位后能一次判别。

**时间**：0.5–1 天。

## T5 kp A/B（仿真，仅站姿）

**目的**：量化 `τ/kp` 对后腿静差的影响，为实机 A/B 提供预期。

**做法**：kp55/kd2 vs kp65/kd2 vs kp85/kd3.2；零命令、同姿态、同 7.7 s；记录后腿 `cmd−actual`、pitch、四轮 Fn、base z。

**产出**：`kp_ab_sim.json` + 曲线。

**判据**：给出三档的静差与姿态；**明确标注这是仿真，实机未验证**。

**时间**：0.5 天。

## T6 修 MuJoCo 包装并重建验收链

**目的**：旧的 `mujoco-mujoco_eval.py` 用 `deploy_ref_controller.py`，与 C++/yaml 不一致（64% 动作元素 |a|>1、腿差 0.1616 rad、轮差 10.9488 rad/s）。在修好之前，"MuJoCo 通过"不能作证据。

**做法**：
1. 用 `13_contracts_assets/himloco/himloco_controller.cpp` + `deploy.yaml` 的语义重写 Python 包装；
2. 用同一份 ≥60 帧夹具，逐帧对比 C++ / Python / ONNX / MuJoCo；
3. 输出每帧最大差与首个分歧帧。

**产出**：`wrapper_parity.json`、新的 `mujoco_eval` 脚本、对比曲线。

**判据**：逐帧最大误差 ≤ 预注册容差（建议 1e-5 量级）；否则不算通过。

**时间**：0.5–1 天。

## T7 复跑 T3-3（我们的 zero-B 四变体）

**目的**：确认我们的同合同 MuJoCo 结果可复现，并解释左右不对称。

**输入**：`12_our_sim_runs/t3_3/`（场景、策略 ONNX、输入包、脚本、6 份结果 JSON）。

**做法**：按 `code/zerob_sim.py` 复跑基线；核对后腿差 0.133/0.378/0.196/0.381、pitch −9.17°、z_min 0.340；再核对四轮 Fn（FL 34/FR 55/RL 65/RR 102 N）。

**产出**：`t3_3_reproduce.json` + 差异说明（环境版本、随机性、接触差异）。

**判据**：关键数字在 ±5% 内；若不一致，定位原因（不是"重跑一次"）。

**时间**：0.5 天。

## T8 门禁可满足性（右移 skating + 三轮支撑）

**目的**：把验收改成物理可达的判据，并在仿真里验证"可达且可判定"。

**做法**：
1. 右移改 skating：允许 RR 持续滚动；禁止非轮触地；侧向速度方向正确；不持续横滑；姿态/轮载稳定；
2. 统计"持续三轮支撑"的窗口（1 s 内占比 <5%）；
3. 用现有权重跑 6 次，给出通过/失败与理由。

**产出**：`gate_feasibility.json` + 判据定义（写进配置）。

**判据**：右移 skating 判据在仿真里可稳定通过；三轮支撑统计可复算。

**时间**：0.5 天。

## T9 官方偏航基准（有数据才做）

**目的**：给"转向弱"一个参照——官方 AS2-W 踏步转向能转多快。

**做法**：如果有官方 `ai_free_walk` 的 LowState 参考（站立/行走/转向），提取同量级 wz 指令下的 gyro_z 稳态与调节时间；没有就写 `UNKNOWN` 并说明缺什么。

**产出**：`official_yaw_baseline.json` 或 `UNKNOWN` 说明。

**判据**：给出"指令 wz → 实测 wz"的斜率与延迟；用于对比策略的 0.146–0.199。

**时间**：0.5 天（取决于数据）。

## 交付格式（统一）

每个任务建 `runs/sim_<task>_20261122/`，包含：
- `config/`（场景/资产/参数，含 SHA）
- `results/*.json`（原始，不要只截图）
- `docs/SUMMARY.md`：一页结论（数字 + `CONFIRMED/OBSERVED/INFERRED/UNKNOWN` + 还缺什么）
- `SHA256SUMS.txt`

**禁止**：改正式 URDF/MJCF/USD；用旧包装跑"验证"；把仿真通过写成实机可用；跨策略借证据。
