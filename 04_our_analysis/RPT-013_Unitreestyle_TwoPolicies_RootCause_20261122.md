### 2.2 根因分层

**R1（训练/能力/门禁设计）——三条独立证据**

1. **门禁与奖励结构性错配（新增证据，来自 `index.html`）**：`unified_dr` 的 `calibration.json` 用 eligible 掩码把 16 个"方向×轮"组合中的 **7 个标成不可得分**（left 缺 RR、right 缺 RL、yaw_left 只 RR、yaw_right 只 FR/RL），而验收要求**四轮各 ≥2 次抬轮** → 结构性不可能通过。结果 unified_dr 三阶段全部 `qualified=false`（失败项 32/33/31）。**这不是训练不够。**
2. **right 方向是几何死结**：`index.html` 明确"支撑三角形 FR–RL 边过重心投影，属几何约束；15 个训练臂 + 15 mm 配重均无效"，部署因此把 `|vy| ≤ 0.10` 锁死。→ 该方向的门禁在现有平台几何下不可达，**继续训也不会过**。
3. **步态没有轮差速通道**：v2-step 删掉了 vx，轮速只由 vx 驱动（`wheel = vx/R`），**转向完全靠踏步**。这决定了偏航带宽上限；README 的下一步把"部署侧 wz 前馈/轮差速"列为候选新版本（属于合同变更，需单独验收）。

**R3（仿真资产/接触）——一条已量化、一条未解**

1. **摩擦（已量化、已对齐、但未解决问题）**：训练用 μ=0.5、实机约 0.25。刚性保持口径（kp=200）前髋负载 **1.66 → 11.91 Nm**，实机 **11–12 Nm**（差 <1%）；而未对齐时差 7 倍。**这是"训练域从未覆盖实机"的硬证据**（`docs/friction-unmodeled-20261120.md`）。
   - 但 **μ025 重训 600 轮上机后，实机转向反而更弱**（0.146 vs 0.199）→ **否定"摩擦对齐即可修好转向"**。
   - DR 区间也错：`domain_config.json` 历史区间 **0.5–1.0**（比标称 0.5 更高），实机 0.25 从未进入训练分布。
2. **后髋载荷分布未解**：仿真 6.0–9.6 Nm vs 实机 **13–15.2 Nm**；COM x −10…−40 mm 扫描不单调（前髋降、后髋不升）→ 指向接触/几何分布（轮位、质心高度、接触面），不是单一质心平移。`UNKNOWN`。

**R2（合同）——部署侧限制，不是缺陷**

- 实机被限制在 `|vy| ≤ 0.10`、`wz ≤ 0.30`（right 方向锁死），所以"实机转向弱"是在**很窄的包络里**测的；不能外推为"策略完全不能转"。
- 部署合同本身与训练一致（tanh、5 Hz 滤波、55/2），**没有发现合同漂移**（与 HIMLoco 不同）。

### 2.3 为什么"tanh + 抖动随机化"有效，而"摩擦对齐"无效

- tanh + 抖动随机化直接作用于**动作平滑性**：符号翻转 30%→8.2%，roll 左倾消除。这是训练侧修好的问题（`R1` 类），现场已验收。
- 摩擦对齐作用于**载荷尺度**：它把仿真负载从 1/7 拉到 ≈实机，但**没有改变"转向靠踏步 + 轮无差速"这一结构**，所以转向带宽不变，甚至因为策略在低摩擦下更保守而更弱（−0.026 斜率）。

### 3.3 HIMLoco 实机部署问题：四层拆解（这才是问题所在）

**L1 参数—负载层：kp=55 对实机静载不足（主因，`CONFIRMED`）**

零命令下腿目标≈默认角，实际角由静力矩平衡决定：`q_actual ≈ q_cmd − τ_gravity / kp`。

- 实机：RL/RR calf `cmd−actual` +0.336/+0.331、thigh +0.237/+0.239 rad（合计 ≈0.57 rad → 机身下沉 3–4 cm），7 s 内稳定。
- 同合同仿真（RPT-008）：0.13–0.38 rad；**把 kp 55→85、kd 2→3.2，降到 0.07–0.18 rad**，pitch −9.2°→−5.3°（实机 −6.1°）。
- 机制检验：静差 ≈ τ/kp。kp 提高 1.55×，静差降 0.29–0.43×，方向一致（大腿更低是因为力矩小、几何耦合）。
- 因此这是**"参数（kp55）与真实负载不匹配"**，不是"训练用一套、部署用另一套"。

**L2 训练集接触/载荷层：策略是在"仿真静差仍在"的世界里训出来的（`OBSERVED`，来源为交付方自述）**

`deployment-contract-18200.md:92` 与 `field-bringup-checklist.md:73` 自己写明：

> "sim2real 静差未解决：保持实测 T2 姿态时仿真俯仰比实机多约 7.5°，前髋力矩约为实机一半（3.7–5.1 vs 11–12 Nm）。**本策略在该静差下训练**，上机前需先用小步速、低增益试跑。"

这与 sim2real 包的结论同源：实机有有限接触斑/横向力，仿真（单点接触）静载只有实机的一半。⇒ 策略学到的"重力补偿量"按仿真的小负载标定；实机负载大 2 倍，于是同一个 kp 下静差更大。**归因是 sim2real 静态接触/载荷差异，不是 kp 数值抄错。**

**L3 部署序列层：不同阶段用不同增益，而 handoff 只平滑目标、不平滑增益（`INFERRED`，未实测）**

| 阶段 | 增益 | 来源 |
|---|---|---|
| A 段 FixedStand（HIMLoco 本次） | kp **55**（与策略同） | `deployment-contract-18200.md:68` 状态机 |
| T15 站姿（历史实践） | **85 / 3.2** | INDEX 2026-11-17；RPT-005 §9 |
| 原厂 `ai_stand_up` | **200 / 4** | INDEX 2026-11-19 诊断节 |
| 原厂 `ai_free_walk` | **40 / 1** | 同上 |
| 策略相位 kp65 候选 | **65 / 2** | `deploy-drive-kp65.yaml`（未执行） |

`himloco_controller.cpp` 的交接只对**目标**做 `ramp_w=(k+1)/100` 斜坡（`applied = ramp_w * target`），**没有对刚度做斜坡**。若现场用 85/3.2 或 200/4 起站、再按 B 切到 55/2 策略，B 按下瞬间就是一次"刚度阶跃 + 目标跳变"。这条**没有任何实测记录**，标 `UNKNOWN`；但它是"为什么接管瞬间容易出问题"的一个合理候选（与 R2000A 的交接 1.4 s HARD 停、R284 的 B 后振荡是同类型问题，属不同族，不互证）。

**L4 合同细节层：与 kp 无关、但常被混为一谈（`CONFIRMED`）**

| 项 | 训练 | 部署 | 状态 |
|---|---|---|---|
| 100 步零命令交接 ramp | 有（`w=(k+1)/100`） | **原本缺失**，控制器第一步就下发 lerp 后目标（≈0.1 rad，训练只给 1%） | **已修复**：补齐后 `MAX_LEG_STEP` 0.1206→0.0582 rad，C++↔Python parity 1.19e-07 |
| 执行延迟 | DR 见过 0/1 两档 | 0 延迟 | 已知差异，未覆盖 1 档 |
| 相位初值 | 每回合随机 | 固定 0 | 已知差异（分布内） |
| 观测里的 applied | 用斜坡值 | 同 | 已对齐 |

⇒ 这些是**合同细节**，修好了 ramp 之后就不是主因；它们解释"首帧冲击"，不解释"持续 0.33 rad 下沉"。

### 3.4 为什么"offset 补偿"不行、"kp85"不能照搬

- **静态 offset 改的是几何而不是刚度**：把后腿目标抬高 0.34 rad，确实把后腿顶起来（RL_calf 0.336→0.105、RR_calf 0.331→0.199），但重心前移、前腿被迫反向对抗，`FR_thigh` 从 −0.004 过冲到 **−0.305**、`FL_calf` 变差（0.006→0.142），并出现持续力矩嗡鸣；操作员 2.2 s 后按 X，offset 全退回 0（`field-sink-analysis.md` §4）。⇒ **不要再用 offset 修下沉**。
- **kp85 只在"地面"口径成立，不能从悬空推**：sim2real `13_PHASE_J` Q7 明确"悬空 kp 扫角只验证执行器静特性，**禁止据此给地面高 Kp 建议**"。我们的 kp85 结果是**地面同合同 zero-B 仿真**（不是悬空），所以可以作为"地面 A/B 候选"，但**仍需实机地面 A/B 验证**（同姿态、同命令、同 7.7 s、记录 `cmd−actual`/Fn/tilt）。
- **kd 的作用**：3.2 主要压落地振铃与速度阻尼；静态下沉量由 kp 主导，别把 kd 当主修法。

### 3.5 可执行修法（不需要新权重，按顺序）

1. **先读、再改**：从发布端日志/固件回读确认 A 段与策略段**实际下发的 kp/kd**（55/2 vs 85/3.2 vs 200/4），确认 A→B 是否存在增益阶跃；这一步只读，不需要动作。
2. **zero-B 验收加一列**：记录 `leg_cmd − leg_actual` 稳态值（现在只记 B 门 `pose_error=0.202`，看不出 0.33 rad 下沉）。
3. **地面 kp A/B**（仅站姿/交接起点）：55/2 vs 85/3.2，同姿态同命令，比较 `cmd−actual`、四轮 Fn、tilt；需现场逐次同意。
4. **不要**再用静态 offset；**不要**用悬空 kp 数据推地面结论。
5. 若后续要动策略：先解决 L2（接触/载荷对齐，见 RPT-015 的 P0/P1），否则重训只会把"仿真小负载"学得更牢。

## 5. `index.html` 与 `任务书.md` 提供的额外信息（此前未进入我们的报告）

`index.html`（92.7 KB，交互任务书，2026-11-21，commit 740b5df）里**独有**的结论：

1. **门禁/奖励结构性错配**：`calibration.json` eligible 掩码只覆盖 9/16 组合（7 个不可得分），而 gate 要求四轮各 ≥2 → unified_dr 三阶段 `qualified=false`（32/33/31 项）"不是训练不够"。

3. **摩擦 DR 区间写错**：历史 `0.5–1.0` 高于标称 0.5，实机 0.25 从未覆盖；建议 `static 0.25–0.50 / dynamic 0.18–0.35`，并以 `as2w-t2-v2-mu025.usd` 为标称资产。
4. **机械参数**：T2-v2 整机 27.5 kg（与我们 URDF 账本 27.512 kg 一致）；控制周期 20 ms（5 ms × 4）；4096 env × 48 steps = 196,608 env-steps/更新。
5. **奖励量级**：塑形项只有跟踪项的 1% 量级，提权 5 倍仍同量级 → **先改结构（门控/事件/覆盖）再改权重**。

`docs/next-training/任务书.md`（18.4 KB）：下一轮训练的父权重选择、资产/控制配置、包络 7 步定标、DR 排程、奖励按命令/阶段设计、权重筛选与现场问题清单。

**审计意见**：`index.html` 的第 1 条（门禁/奖励错配）**必须进入交付合同检查项**——它意味着"某个方向门禁 FAIL"可能根本不是策略能力问题，而是验收判据本身不可满足。这与我们 RPT-010 在 R2000A 上看到的"边界脆弱/判据不可满足"是同类问题（不同族，不互证）。

## 7. 不可混用声明

- v2-step 与 HIMLoco 是**两条独立训练线**（58/12 vs 360/16），本文只做"同平台、同问题类型"的并列，不把一条的结论当另一条的证据。
- **"kp/kd 一致"只指参数数值一致**（腿 55/2、轮 0/2），**不表示动力学一致**：同一组 kp/kd 在仿真与实机上的等效刚度不同（接触/载荷不同），这正是 L2。
- v2-step 的摩擦数字（1.66→11.91 Nm）是**仿真资产口径**，不是实机称重。
- HIMLoco 的 kp85 结论来自**同合同地面仿真**（RPT-008），不是悬空推地面，也**未做实机 A/B**；T15 的 85/3.2 是另一族，不可直接搬。
- "转向弱"在两条线都**没有同合同实机证据**：v2-step 有 0.199/0.146 斜率（窄包络），HIMLoco 未测。
- 增益阶跃（A 段 85/3.2 或 200/4 → B 段 55/2）**没有任何实测**，只能作为候选机制。
