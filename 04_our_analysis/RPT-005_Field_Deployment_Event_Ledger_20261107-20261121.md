## 14. 怎么用这张表

1. **先认族再读结论**：同一天可能有两个族在跑；`族/对象` 列不同的行**不能**互相解释。
2. **实机动作行才是“行为证据”**；离线/编译行只能证明“离线门槛通过”。
3. 需要原始细节：按 `INDEX#` 到 `部署测试/04_调试记录/INDEX.md` 找同名小节（本表标题即 INDEX 标题的浓缩）。
4. 需要原始日志：`部署测试/04_调试记录/logs/` 下按日期/主题命名。
5. 引用时至少写：`INDEX# + 日期 + 族 + 等级`。

## 16. 与交接 §8 schema 的映射

| schema 字段 | 本表列 | 备注 |
|---|---|---|
| `event_id` | `INDEX#` + 日期 | 例：`IDX-149-20261110` |
| `strategy_family` | 族/对象 | R152/R214/R249/R270/R284/R1199/R4000/getup1199/T15/armD/RISE63/HIMLoco/R2000A |
| `weight_sha` / `onnx_sha` | （缺） | 仅少数行在 INDEX 正文给出；需逐条补 |
| `deploy_binary` / `build` | 事件描述内 | 如 `build-r214-ab-fsm`、`build-r1199-forward` |
| `obs/action_contract` | （按族见 RPT-003/004 与观测汇总） | 不逐行重复 |
| `runtime_flags` | 事件描述内 | 如低通 40 ms、kp/kd 85/3.2 |
| `initial_state` / `command` | 事件描述内 | 实机行基本都有 |
| `environment` | 类型列 + 说明 | 实机 / MuJoCo / Isaac / 离线 |
| `result` / `protection` | 事件与结果 | 保护位、RC 码、`motorstate_or` |
| `log_path` | （缺） | INDEX 正文给出；待批量补 |
| `evidence_level` | 等级列 | 默认 `OBSERVED` |
| `ruled_out / not_ruled_out` | 大事件行内 | 待系统化 |
