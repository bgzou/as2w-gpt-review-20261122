# 两个上机策略到底出了什么问题（v3，2026-11-22）

> 这份文档写给**没看过任何项目文件的人**。每个数字都会先说清"它是在说什么"，再给数值；出处集中放在最后一节，正文只在必要处点一句。

---

## 0. 一页看懂

**机器人**：AS2-W 是"轮腿"机器人——四条腿各有髋/大腿/小腿 3 个关节（共 12 个），每条腿末端是一个驱动轮（共 4 个）。腿用**位置伺服**（给目标角，电机按 `力矩 = kp×(目标−实际) − kd×速度` 去追，本项目 kp=55、kd=2），轮用**速度伺服**（给目标转速）。控制频率 50 Hz（每 20 ms 一次）。

**两条策略**（同事训练，都上过实机）：

| 策略 | 它想干什么 | 观测/动作 | 特点 |
|---|---|---|---|
| **v2-step** | 只做"侧移 + 转向"的踏步，**不做前后滚动** | 58 维观测 / 12 维腿动作 | 前后移动交给轮子（本项目里被移除），侧移/转向靠腿周期性抬落 |
| **HIMLoco** | 腿轮联合：前后、转向、站立都用一套网络 | 360 维观测 / 16 维动作 | 腿和轮一起输出，带 100 步"零命令交接"斜坡 |

**上机后看到的两件事**：

1. **v2-step**：站着不动时腿在抖；用摇杆让它侧移/转向，机器人**几乎不动**（下指令转 0.10 rad/s，实测只有 0.026 rad/s）；往右走时**右后轮从来不抬**。
2. **HIMLoco**：能站、能走，但在推杆过程中**两条后腿被体重压下去**（小腿的目标角与实际角差约 0.33 rad，换算成机身下沉约 3–4 cm）；想用"把目标角抬高"去补，结果前腿被顶反、机身前倾、关节嗡鸣，只能急停。

**根因一句话**：

- **v2-step 主要是"训练目标与训练数据"的问题**：门禁要求了一个几何上做不到的动作（右后轮抬起）、奖励算分机制本身有 7/16 组合不可得分、步态没有轮差速所以转向只能靠踏步、训练用的地面摩擦比实机高一倍。**不是"实机太滑"这么简单，也不是"策略笨"**。
- **HIMLoco 主要是"腿的弹簧太软 + 训练世界比实机轻"**：kp=55 对实机重量不够（静差≈重力矩/kp），而训练时的仿真里前髋力矩只有实机的一半（3.7–5.1 vs 11–12 Nm）。**不是策略不会站，也不是 kp/kd 抄错**。

## 1. 先解释几个会反复出现的词

| 词 | 意思 |
|---|---|
| **零命令** | 不给任何运动指令（vx=vy=wz=0），让机器人自己站着。这是看"站得稳不稳"的基准。 |
| **B 键 / 交接** | 现场状态机：A 起立 → B 把控制权交给策略。HIMLoco 在交接的前 100 步（2 s）会把策略输出从 0 线性拉到全量，避免第一帧跳变。 |
| **`cmd−actual`（目标−实际）** | 关节"想去的角度"减"实际角度"。**正值 = 实际角比目标低，也就是腿被重力压下去了**；负值 = 实际比目标高。 |
| **p2p（峰峰值）** | 一段时间内最大值减最小值，用来衡量"抖得有多厉害"。 |
| **符号翻转率** | 相邻控制周期里，腿目标角的变化方向反转的帧占比。越高越"抖"。 |
| **yaw 斜率** | 实测偏航角速度 ÷ 指令偏航角速度。1.0 = 完全跟上，0.1 = 只跟到一成。 |
| **PD 力矩** | 用 `kp×(目标−实际) − kd×速度` 算出来的"电机要出多大力"，不是实测力矩。 |
| **Fn** | 轮子压在地面上的法向力（N）。四轮 Fn 之和≈整机重量。 |
| **门禁（gate）** | 训练/验收的通过条件，例如"四个方向、每个轮子都要抬起至少 2 次"。 |

## 2. v2-step：到底看到了什么

### 2.1 站着不动时，腿在抖

**现象**：机器人不给指令站着时，腿的目标角在约 ±0.18 rad 范围内来回翻（峰峰值 0.36 rad），大约每秒翻转 8 次；机身会轻微左倾。现场能听到关节的轻微"哒哒"声。

**数字**（两版权重）：

| 指标 | jit 权重 | mu025 权重 | 说明 |
|---|---:|---:|---|
| 腿目标峰峰值 | 0.360 rad | 0.369 rad | 抖的幅度，约 20° |
| 符号翻转率 | 8.17% | 12.85% | 越高越抖；mu025 反而更差 |
| 机身 roll 均值 | −2.49° | −0.58° | mu025 把左倾修好了 |

**为什么是问题**：目标角高频翻转会让关节/减速器反复换向，发热、磨损、噪声；也是"策略输出不平滑"的直接证据。旧版本（还在用"直接截断到 ±1"的动作方式时）据会话记录翻转率约 **30%**，但那份原始时间序列没有归档，只能标"记录值"，不能算复算值。

**已经修好的部分**：把动作从"截断"改成 `tanh`（平滑压缩）并加"电机抖动随机化"训练后，翻转率从约 30% 降到 8.2%——这一步是训练侧修好的。

**没有修好的部分**：μ=0.25 重训的那版又回到 12.85%，说明"抖动"不是一次修完的。

### 2.2 让它侧移/转向，几乎不动

**现象**：用摇杆给侧移 0.2 m/s、转向 0.3 rad/s，机器人基本在原地踏步/打滑，位移很小，转向很慢。

**数字**：

| 指标 | jit 权重 | mu025 权重 | 说明 |
|---|---:|---:|---|
| yaw 斜率 | 0.199 | **0.146** | 指令转 1 rad/s，实际只转 0.15–0.2 |
| 实测/指令（活动帧） | — | 指令 0.103 → 实测 **0.0256** rad/s | 约 1/4 |
| 侧移斜率 | 0.709 | **−1.141** | mu025 的侧移方向甚至反了 |
| 侧移活动帧占比 | — | 15.6%（另一次试验 7.6%，口径不同） | 大部分时间没有有效侧移 |

**为什么是问题**：这条策略被设计出来就是干"侧移 + 转向"的；这两项几乎不工作，等于任务没完成。

**一个重要的否定结果**：有人认为是"训练地面摩擦 0.5、实机 0.25，策略在实机打滑"。于是用 μ=0.25 重训 600 轮再上机——**转向反而更差**（0.146 < 0.199）。所以摩擦是重要背景，但**不是转向弱的全部原因**。

### 2.3 往右走：右后轮永远不抬

**现象**：训练和验收要求"四个方向、四个轮子都能抬起至少 2 次"。往右时，**右后轮（RR）一次都没抬起来过**。

**数字**：8 条主要训练臂的 `event_right_RR` 最终都是 0；把训练臂扩到 15 条、甚至把质心往左偏 15 mm，仍然 0 次。

**原因（几何）**：抬起 RR 后，剩下三个支撑点是左前（FL）、右前（FR）、左后（RL）。这三个点组成的三角形，有一条边（FR–RL）正好穿过整机重心的投影——**静态稳定裕度是 0**。所以机器人一抬 RR 就会往右倒，控制再努力也稳不住。

**结论**：这不是"训练不够"，是**几何上做不到**。把"右后轮抬起"当验收条件，等于要求一个不可能的动作。

## 3. v2-step：根因是什么

### 3.1 训练目标的问题（三条）

**（1）门禁要求了做不到的动作。**
`unified_dr` 这条训练线里，奖励的"资格掩码"把 16 个"方向×轮"组合中的 **7 个标成不可得分**（左移缺 RR、右移缺 RL、左转只认 RR、右转只认 FR/RL）。而验收要求"四轮各 ≥2 次"——**两边对不上，验收在结构上不可能通过**。结果三阶段分别有 32/33/31 项失败。这是"门禁设计错误"，不是训练不够。

> 注意：这个错在 `unified_dr` 线；v2-step 的两个上机权重（jit/mu025）不是直接继承它，但不能排除同类的"判据不可满足"问题。

**（2）右方向是几何死结**（见 2.3）。

**（3）步态没有"轮差速"这个通道。**
v2-step 删掉了前后移动，轮速只由 vx 决定（`轮速 = vx / 轮半径`），所以**转向完全靠腿踏步**。宇树官方的 AS2-W 也是这么做的，所以这**不是设计错误**；但它意味着"踏步必须自己产生足够的偏航力矩"。现在踏步产生的力矩不够（轮胎打滑），而我们没有"官方踏步能转多快"的基准，所以说不清是"策略没学会"还是"平台就只能这样"。

### 3.2 训练数据的问题（一条主因 + 一条未解）

**（1）训练用的地面摩擦是实机的两倍。**
训练资产 μ=0.5，实机估计约 0.25。在"刚性保持"（kp=200，让关节几乎不动，测真实负载）口径下，同一姿态前髋负载从 **1.66 Nm（μ=0.5）** 变成 **11.91 Nm（μ=0.25）**，而实机实测 **11–12 Nm**——几乎完全对上。换句话说，**仿真里地面"抓地力"多一倍，策略学的是"抓着地踏步"，到实机上轮胎打滑，踏步的偏航力矩就没了**。

但注意：0.25 是估计值，**没有独立测量**；而且 μ=0.25 重训并没有修好转向（见 2.2）。

**（2）后腿载荷分布仍然不对。**
仿真里后髋负载 6.0–9.6 Nm，实机 13–15.2 Nm；把质心前后移动 −10…−40 mm 也不能单调改善（前髋降、后髋不升）。这说明是**接触/几何分布**问题（轮位、质心高度、轮胎接触面），不是简单"质心偏了"。这一项**没有定案**。

### 3.3 部署映射：还没排除

12 个腿关节的"正方向"和"零位"没有做过统一核对。早期现场人工标定记录 hip 符号是 **−1**，而后期重力锚定的表述是 **+1**（可能是坐标系约定不同），两者没有被对齐。

这是**最便宜、也最可能一票否决训练假设**的实验：固定站姿，对单个关节下 `+0.02 rad` 的目标，保持 2 s，看实际角度往哪边动；12 个轴各做一遍，和仿真同命令对比。如果发现某个轴方向相反，那"转向弱"就直接是部署映射问题，和训练无关。

### 3.4 证据本身的问题

- **30% 翻转率**没有原始时间序列，只能算记录值；能复算的是 8.17% 和 12.85%。
- **7.6% 与 15.6%** 是两个不同统计口径（一次试验的有效帧 vs 另一段的"活动帧"占比），不能混着说。
- 上机权重有三个不同 SHA（`45b36` 是交付版、`99995126` 是 jit、`a3215` 是 mu025），比较时必须认准。

## 4. HIMLoco：到底看到了什么

### 4.1 能站、能走，但后腿被体重压下去

**现象**：A 起立 → B 交接成功（交接时的姿态误差 0.202 rad，机器人基本是站姿）→ 零速保持 → 自动刹车 → 回站 → 退出，**没有硬件告警**。随后用摇杆推杆（前后 −0.30…+0.036 m/s，转向 0…0.108 rad/s）时，两条后腿明显"塌下去"。

**数字**（推杆过程中的"目标−实际"）：

| 关节 | 平均差 | 最大差 | 换算 |
|---|---:|---:|---|
| 左后小腿（RL_calf） | **0.336 rad** | 0.350 | 小腿差 0.34 rad ≈ 机身下沉 3–4 cm |
| 右后小腿（RR_calf） | **0.331 rad** | 0.376 | 同上 |
| 左后大腿（RL_thigh） | 0.237 rad | 0.278 | |
| 右后大腿（RR_thigh） | 0.239 rad | 0.279 | |

**关键理解**：这不是"策略在往下压"。策略给的目标是一个正常站姿角，但腿的 PD **撑不住体重**，实际角被压低了 0.33 rad——就像弹簧太软，挂上重物就下去一截。7 s 内这个差值是稳定的、不增长的，说明是**静态承载**问题，不是发散。

**必须说清的口径**：这组数字来自**推杆那一轮（18:33）**，不是"纯零命令站着不动"的静态试验。零命令那一轮（18:14）只验证了"交接能成、能保持、能退出"，**没有逐轴量化下沉**；而且那一轮的发布端日志没有归档，持续时间只能写"未知"（时间线写 60 s 上限，事件汇总写 7.7 s）。

### 4.2 想用"把目标抬高"补偿，失败

**现象**：给后腿的目标角加 +0.34 rad 的偏移（想让腿"提前伸直"一点来抵消下沉）。后腿确实起来了（小腿差从 0.336 降到 0.105，大腿从 0.237 降到 0.020），但：

- 前腿被顶得反向：右前大腿（FR_thigh）从 −0.004 变成 **−0.305 rad**；
- 左前小腿（FL_calf）从 0.006 变成 0.142；
- 机身持续前倾，关节出现力矩嗡鸣；
- 操作员 2.2 s 后按 X 急停，偏移全部退回 0。

**为什么失败**：offset 改的是"目标几何"，不是"腿的刚度"。把后腿拉长，整机重心前移，前腿就必须用更大的反向力去撑——问题只是从后腿转移到了前腿。

### 4.3 其他已知

- 前进/后退在仿真里可以（跟踪 85–92%），实机也试过 −0.30 m/s；**转向/横移实机没测**。
- 有一次"MuJoCo 验证通过"的记录，但它用的 Python 参考控制器和真正部署的 C++ 包装**不一致**（腿目标差 0.16 rad、轮目标差 10.9 rad/s），所以那条不能当"仿真里是好的"的证据。

## 5. HIMLoco：根因是什么

### 5.1 先排除"训练和部署的 kp/kd 抄错了"——没有

| 项目 | 训练 | 部署（C++/yaml） |
|---|---|---|
| 腿 kp / kd | 55 / 2 | 55 / 2 |
| 轮 kp / kd | 0 / 2（速度伺服） | 0 / 2 |
| 动作 | `tanh → ×0.6 → ×0.25` | 相同 |
| 轮目标 | `(vx−wz·side)/R + 2·tanh` | 相同 |
| 腿/轮滤波系数 | 0.7154 / 0.4665 | 相同 |
| 交接斜坡 | 100 步 | 已补齐 |

训练时还会对增益做 ±5% 随机化，所以部署的 55/2 正好在训练分布中心。**"两边参数不一致"这个假设可以排除。**

### 5.2 真正原因：弹簧太软 + 训练世界太轻

**（1）弹簧太软（机制）**：静差 ≈ 重力矩 ÷ kp。同一套策略、同一个仿真、只把 kp 从 55 提到 85（kd 从 2 提到 3.2），后腿差从 **0.378 → 0.110 rad**（RR 小腿），pitch 从 **−9.17° → −5.26°**，而实机 pitch 是 −6.13°——**kp85 的仿真结果反而更接近实机**。

> 注意：这是**仿真**，不是实机 kp85 试验；而且 kp、kd 是一起改的，不能把改善全归给 kp。

**（2）训练世界太轻（为什么实机更严重）**：交付方的合同文档自己写着"仿真俯仰比实机多约 7.5°，**前髋力矩只有实机的一半（3.7–5.1 vs 11–12 Nm）**，本策略在该静差下训练"。也就是说：策略学"用多大力气撑住身体"时，看到的是一个**比实机轻一倍**的世界；到实机上，同样的 kp 自然撑不住。

**（3）同合同仿真也会下沉，但载荷分布不同**：
我们用与 C++ 完全一致的动作包装，在 MuJoCo 里复跑零命令，末 3 s 的后腿差是 **0.13–0.38 rad**（和实机同量级）。但四轮法向力分布是 **左前 34 / 右前 55 / 左后 65 / 右后 102 N**（左右不对称、右后最重），而实机反演是 **48/48/80/80 N**（左右对称）。所以：
- **机制**（kp55 + 重力 → 静差）在仿真里就能复现，不需要"实机独有的东西"；
- **定量**（谁承受多少、前髋力矩多大）仿真和实机不同，这是真正的 Sim2Real 载荷/接触差异。

### 5.3 一个还没验证的猜测：交接瞬间"变软"

站姿段现场可能用 85/3.2 或原厂 200/4，按下 B 后变成策略的 55/2；而 100 步交接斜坡只平滑**目标角**，**不平滑刚度**。如果确实如此，B 按下瞬间刚度会阶跃下降。这条**没有实测记录**，只能算猜测。

### 5.4 已经修好的合同细节

控制器原来缺少 100 步零命令交接斜坡，第一帧就把"插值后的目标"（约 0.1 rad）发下去，而训练只给 1%。补齐后，最大腿目标跳变从 **0.1206 → 0.0582 rad**。这解释了"首帧冲击"，但**不解释持续的 0.33 rad 静差**。

## 6. 两条线的结论对照

| | v2-step | HIMLoco |
|---|---|---|
| **主要症状** | 站着抖；侧移/转向几乎不动；右后轮永不抬 | 推杆时后腿被压下去 0.33 rad；offset 补偿失败 |
| **主要原因** | 训练目标错（右向几何死结、门禁算分错配、无轮差速）+ 训练数据错（摩擦高一倍） | 腿的 kp=55 余量不足（τ/kp）+ 训练世界载荷只有实机一半 |
| **sim2real 的角色** | 摩擦是必要背景，但不充分（对齐后转向更差） | 载荷/接触分布不同是"为什么实机更严重"，但机制在仿真里就能复现 |
| **要不要重训** | 可能，但先把 P0 核对、门禁、几何与摩擦基准做完 | 不需要（没有能力失败证据） |
| **该动哪一层** | 训练目标/数据 + 一个部署核对 | 部署增益（站姿 kp）+ 载荷口径 |

## 7. 还没解决、必须靠测量的问题

1. **四轮 Fn 真值**：现在实机的 48/48/80/80 N 是"反演"出来的，不是称出来的。
2. **接触斑/轮胎压缩/真实摩擦**：0.25 是估计值。
3. **横向力 Fy 的方向**：实机到底是"外撑"还是"内撑"，没有测过；这是判断接触模型对不对的关键。
4. **12 轴方向/零位**：没做统一核对（可能一票否决训练假设）。
5. **官方踏步偏航基准**：不知道官方 AS2-W 踏步能转多快，就没有"转向弱"的参照。
6. **HIMLoco 18200 vs 9836**：只上过 18200，9836 连文件/SHA 都还没有。
