## 1. 结论速览

| 线 | 现场症状 | 根因判定 | 训练 or Sim2Real |
|---|---|---|---|
| **v2-step** | ①零命令腿目标抖动 ②侧移/转向几乎不动 ③right 方向门禁不可达（RR 不抬） | 训练侧为主：**门禁/奖励结构性错配（属 unified_dr 线）**、**步态无轮差速通道**、**训练域摩擦未覆盖实机**；外加 right 方向几何死结 | **主要是训练与训练域**；摩擦是必要背景但**不充分**（对齐重训后实机转向未改善） |
| **HIMLoco** | ①推杆工况后腿静差 0.336/0.331 rad ②−6.1° pitch ③静态 offset 补偿失败 | **部署参数 kp=55 承载余量不足（机制 τ/kp）+ 训练集载荷口径低于实机**（仿真前髋 3.7–5.1 Nm vs 实机 11–12 Nm） | 训练能力未见失败证据；**不是单纯 Sim2Real 植物差异**（同合同仿真同样下沉），也不是 kp 抄错 |

**一句话**：step 的问题在"训练目标/门禁/训练域"；HIMLoco 的问题在"部署增益余量 + 训练集负载口径"。

## 2. v2-step 的根因拆解

### 2.1 症状与数字（含口径修正）

| 现象 | jit 权重 | mu025 权重 | 来源 |
|---|---|---|---|
| 零命令腿目标 p2p | 0.360 rad | 0.369 rad | `analysis/field-metrics-summary.json` |
| 零命令符号翻转 | **8.17%** | **12.85%** | 同上（键 `zeroB_old` / `zeroB_mu025`） |
| roll 均值 | −2.49° | −0.58° | 同上 |
| 前髋 PD 力矩 | 6.19/3.98 Nm | 5.32/4.90 Nm | 同上 |
| yaw 斜率 | 0.199 | 0.146 | `analysis/field-yaw-lateral-slopes.json` |
| lateral 斜率 | 0.709 | −1.141 | 同上 |
| 摇杆活动帧 | wz 296 / vy 279 | wz 260 / vy 142 | 同上 |
| yaw 跟踪比 | — | **0.188**（指令 0.103 → 实测 0.0256） | `analysis/field-lateral2-analysis.json` |

**口径修正（外部复核指出，已核实）**：

1. **30% 不是本仓库原始数据**：README 写"符号翻转率 30% → 8–13%"，但仓库 `field-metrics-summary.json` 只有 8.17%（`zeroB_old`）与 12.85%（`zeroB_mu025`），30% 对应的旧 clamp 权重**没有完整时间序列**。⇒ 30% 只能标 `OBSERVED`（会话叙述），`CONFIRMED` 的是 8.17% / 12.85%。
2. **mu025 的抖动比 jit 更差**：8.17% → 12.85%，不能用"tanh+抖动把抖动解决了"概括整条线；抖动随机化解决的是 30%→8.2% 这一步，mu025 又退回去。
3. **7.6% 与 15.6% 不是同一口径**：README 的 7.6% 是 18:57 试次的 vy 有效帧；`lateral2` 的 15.6% 是 260/911 活动帧比例，不能混用。

### 2.2 根因分层

**R1 训练/门禁设计（主因之一）**

1. **门禁与奖励结构性错配——属 unified_dr 线，不是 jit/mu025 的直接缺陷**：`unified_dr` 的 `calibration.json` 用 eligible 掩码把 16 个"方向×轮"组合中的 **7 个标成不可得分**（left 缺 RR；right 缺 RL；yaw_left 只 RR；yaw_right 只 FR/RL），而验收要求四轮各 ≥2 次抬轮 → 结构性不可能通过；三阶段 `qualified=false`（失败项 32/33/31）。⇒ 这是**线级门禁设计缺陷**，要修；但不能据此说 jit/mu025 的奖励本身错。
2. **right 方向是几何死结**：抬 RR 后支撑三角形 FL+FR+RL，FR–RL 边过重心投影，静稳定裕度 0；**15 个训练臂 + 15 mm 质心偏移都无法产生一次 RR 抬升**（8 条主臂 `event_right_RR` 最终 0.000000）。⇒ 四轮轮流抬升不是该方向合理目标。
3. **步态没有轮差速通道**：v2-step 删掉 vx 后轮速仅由 `vx/R` 决定，**转向完全靠踏步**。这与宇树官方 AS2-W 做法一致，**不是缺陷**；但意味着踏步必须自己达到目标带宽，而目前没有"官方基准"可比。

**R2 训练域/资产**

1. **摩擦未覆盖实机**：训练 μ=0.5、实机估计约 0.25。刚性保持口径（kp200）前髋负载 **1.66 → 11.91 Nm**，实机 11–12 Nm；默认姿态 kp55 则 0.39 → 5.37 Nm。**0.25 是估计值，无独立实机摩擦测量**。
2. **摩擦对齐不足以修转向（关键否定结果）**：μ025 重训 600 轮后上机，**yaw 斜率 0.146 < 旧 0.199**；同时仿真门禁 right 从 0/4 回到 2/4、yaw_left 从 1/4 回到 3/4。⇒ 摩擦是必要背景，**不是转向弱的充分解释**。
3. **后髋载荷分布未解**：仿真 6.0–9.6 Nm vs 实机 13–15.2 Nm；COM x −10…−40 mm 扫描不单调 → 指向接触/几何分布（轮位、质心高度、接触面），`UNKNOWN`。

**R3 部署合同（不是缺陷，但限制结论）**

- 实机被限制在 `|vy| ≤ 0.10`、`wz ≤ 0.30`，right 锁死；"转向弱"是**窄包络**结论。
- v2-step 的 tanh、55/2、5 Hz 轮滤波**未发现训练↔部署不一致**。
- **但 12 轴正方向/零位没有统一核验**：早期现场人工标定记录 hip sign = −1，而 Phase F 重力锚定的表述为 +1（可能坐标约定不同），**不能视为已解决** → 列为 P0。

**R4 证据质量**

- 权重 SHA 必须区分：`45b36`（DR0 交付）、`99995126`（上机 jit）、`a3215`（上机 mu025）。
- 30% 缺原始序列；7.6% 与 15.6% 口径不同；`zeroB_old` 是 jit 权重，**不是**旧 clamp 权重。

### 2.3 为什么 tanh 有效、摩擦对齐无效

- tanh + 抖动随机化作用于**动作平滑性**：旧 clamp 基线的 30%→jitter 的 8.2%（OBSERVED）；但 mu025 又升到 12.85%，说明抖动不是单调改善。
- 摩擦对齐作用于**载荷尺度**：把仿真负载从 1/7 拉到 ≈实机，但**没有改变"转向靠踏步 + 轮无差速"的结构**，所以转向带宽不变；低摩擦下策略更保守，反而更弱。

### 2.4 待测清单（按成本）

| 优先级 | 实验 | 能排除什么 |
|---|---|---|
| **P0** | **12 轴单关节方向/零位核对**（固定站姿，单轴 `+0.02 rad`，2 s，读 `q`，与仿真对符号） | 若出现反向轴 → 转向弱直接由部署映射解释；同时解决 hip sign −1/+1 的表述冲突 |
| P0 | 四轮称重 + 整机 CoM（26.0/0.035 vs 27.512/0.020） | 质量/CoM 二义 |
| P1 | 官方 `ai_free_walk` 偏航基准（同地面、同量级 wz 的 gyro_z 稳态与调节时间） | "转向弱"是策略不足还是平台上限 |
| P1 | 接触几何单变量（轮半径/轮距/质心高度/接触刚度） | 后髋 2× 分布差 |
| P2 | μ 两档（0.25/0.50）+ 宽区间 DR | 低摩擦下是否存在可行步态 |

### 3.2 kp/kd 是不是"训练与部署不一致"——不是

| 审计项 | 训练 | 部署 | 判定 |

### 3.3 四层拆解

**L1 参数—负载层（主因，`CONFIRMED`）**：`q_actual ≈ q_cmd − τ_gravity/kp`。推杆工况 0.336/0.331；同合同仿真 0.13–0.38；kp85/kd3.2 后 0.07–0.18，pitch −9.2°→−5.3°。注意：**两个增益同时改**，不能把改善全归 kp；且**未做实机 kp85 地面 A/B**。

**L2 训练集接触/载荷层（`OBSERVED`，交付方自述）**：`deployment-contract-18200.md:92` 与 `field-bringup-checklist.md:73` 写明"仿真俯仰比实机多约 7.5°，前髋力矩约为实机一半（3.7–5.1 vs 11–12 Nm）；**本策略在该静差下训练**"。⇒ 策略学到的重力补偿按仿真小负载标定；实机负载大 2 倍。

**L3 部署序列层（`INFERRED`，未实测）**：不同阶段增益不同——A 段 55；T15 站姿 85/3.2；原厂 `ai_stand_up` 200/4、`ai_free_walk` 40/1；`deploy-drive-kp65.yaml` 是策略相位 65 候选（已构建未执行）。handoff 只对**目标**做 `ramp_w=(k+1)/100`，**不平滑刚度**。若现场用 85/3.2 起站再切 B（55/2），就是"刚度阶跃 + 目标跳变"。**无实测记录 → `UNKNOWN`**。

**L4 合同细节层（`CONFIRMED`，已修/已知）**：handoff ramp 原本缺失，补齐后 `MAX_LEG_STEP` 0.1206→0.0582 rad、parity 1.19e-07；训练 DR 有 0/1 步延迟、部署 0；相位初值训练随机、部署固定 0。解释"首帧冲击"，**不解释持续静差**。

### 3.4 关于"Sim2Real"的精确表述

同合同仿真**能复现**后腿静差（0.13–0.38 rad）——所以：
- **机制**是 `τ/kp`（部署增益余量），`CONFIRMED`；
- **为什么实机 τ 更大**：训练集接触/载荷只到实机一半（L2），这是 **Sim2Real 静态载荷差异**；
- 因此正确表述是"**部署增益余量 + 训练集载荷口径**"，而不是"实机植物与仿真不同导致策略失效"；后者会误导为"重训可修"。

### 3.5 offset 与 kp85 的边界

- offset 改几何不改刚度 → 后腿顶起、前腿反向对抗（FR_thigh −0.305）、嗡鸣 → 不要再用。
- kp85 来自**地面同合同仿真**（非悬空推地面），只能算"地面 A/B 候选"，**必须实机地面验证**；目前没有实机 kp85 数据。
