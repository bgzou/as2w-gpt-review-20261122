## 1. 结论速览

| 线 | 现场症状 | 根因判定 | 训练 or sim2real |
|---|---|---|---|
| **v2-step** | ①零命令腿目标抖动（符号翻转 30%）②侧移/转向几乎不动（yaw 跟踪 8–19%）③right 方向门禁不可达（RR 轮从不抬起） | 训练侧为主：**门禁/奖励与几何结构性错配**、**步态没有轮差速通道**、**训练域摩擦从未覆盖实机**；外加一条**几何死结**（right 方向静稳定裕度为 0） | **主要是训练与训练域**；sim2real 摩擦是必要背景但**不充分**（对齐后重训，实机转向未改善） |
| **HIMLoco** | ①零命令后腿下沉 0.336/0.331 rad（3–4 cm）②−6.1° pitch ③静态 offset 补偿失败 | **部署参数 kp=55 对实机静载不足**（τ/kp 静差），叠加**训练集接触/载荷偏差**（仿真前髋 3.7–5.1 Nm vs 实机 11–12 Nm，策略在该静差下训练） | 训练能力未见失败证据；**也不是单纯 sim2real**（同合同仿真同样下沉，kp85 减半） |

**一句话**：step 的问题主要在"训练目标/门禁/训练域"；HIMLoco 的问题主要在"部署参数与训练集载荷口径"。两者都不是"策略学会了但被现实打败"这么简单。

## 2. v2-step 的根因拆解

### 2.1 症状与数字（全部有原始文件）

| 现象 | 数字 | 来源 |
|---|---|---|
| 零命令腿目标抖动 | 旧权重符号翻转 **30%** → 抖动随机化 **8.2%**；mu025 **12.85%** | `analysis/field-metrics-summary.json` |
| 零命令姿态 | 旧权重 roll 均值 **−2.49°**；mu025 **−0.58°** | 同上 |
| 零命令髋 PD 力矩 | 旧 6.19/3.98/4.18/5.91 Nm；mu025 5.32/4.90/4.38/3.92 Nm | 同上 |
| 摇杆偏航跟踪 | 旧 yaw 斜率 **0.199**；mu025 **0.146**；0.26 rad/s 指令 → 实测 0.049 | `analysis/field-yaw-lateral-slopes.json` |
| 侧移 | vy 有效帧 7.6%；mu025 lateral 斜率 **−1.141**（方向反了） | 同上 |
| 仿真门禁（4 方向 × 四轮抬升 ≥2） | base μ=0.5：left 4/4、yaw_left 4/4、yaw_right 4/4、**right 3/4**；mu025：4/3/3/**2** | `data/gate-matrix.csv` |
| RR 轮抬升 | **15 个训练臂 + 15 mm 配重，RR 从未抬起**；训练中 `event_right_RR` 最终 0.000000 | session README |
| 训练内抖动指标 | `executed_signflip_fraction` 0.200 → 0.166（DR2+抖动 586 轮） | `docs/jitter-compare-20261120.md` |

### 2.2 根因分层

**R1 训练/门禁设计（主因之一，`CONFIRMED`）**

1. **门禁与奖励结构性错配**：`unified_dr` 的 `calibration.json` 用 eligible 掩码把 16 个"方向×轮"组合中的 **7 个标成不可得分**（left 缺 RR；right 缺 RL；yaw_left 只 RR；yaw_right 只 FR/RL），而验收要求**四轮各 ≥2 次抬轮** → 结构性不可能通过；结果 unified_dr 三阶段全部 `qualified=false`（失败项 32/33/31）。**这不是训练不够。**
2. **right 方向是几何死结**：抬 RR 后支撑三角形为 FL+FR+RL，FR–RL 边过重心投影，静稳定裕度为 0；15 个训练臂（覆盖惩罚、最重轮加权、对角/侧向相位、right-only 课程、半幅命令）+ 仿真 15 mm 左侧质心偏移，**全部无法产生一次 RR 抬升**。部署因此把 `|vy| ≤ 0.10` 锁死。
3. **步态没有轮差速通道**：v2-step 删掉 vx 后轮速仅由 `vx/R` 决定，**转向完全靠踏步**；这决定了偏航带宽上限（与官方 AS2-W 的做法一致，不是缺陷，但意味着踏步必须自己达到目标带宽）。

**R2 训练域/资产（主因之二，`OBSERVED` + `CONFIRMED`）**

1. **摩擦从未覆盖实机**：训练用 μ=0.5、实机约 0.25。刚性保持口径（kp=200）前髋负载 **1.66 → 11.91 Nm**（μ 0.5→0.25），实机 **11–12 Nm**（差 <1%）；DR 区间历史为 **0.5–1.0**（比标称更高），实机 0.25 从未进入训练分布。
2. **但摩擦对齐不足以修转向（关键否定结果）**：μ025 重训 600 轮后上机，**实机 yaw 斜率 0.146 < 旧权重 0.199**。⇒ 摩擦是必要背景，**不是转向弱的充分解释**。同一重训把仿真门禁的 right 从 0/4 拉回 2/4、yaw_left 从 1/4 拉回 3/4，说明策略确实在适配低摩擦，但没换来实机转向。
3. **后髋载荷分布未解**：仿真 6.0–9.6 Nm vs 实机 **13–15.2 Nm**；COM x −10…−40 mm 扫描不单调（前髋降、后髋不升）→ 指向接触/几何分布（轮位、质心高度、接触面），`UNKNOWN`。

**R3 合同/部署（不是缺陷，但限制结论，`CONFIRMED`）**

- 实机被限制在 `|vy| ≤ 0.10`、`wz ≤ 0.30`（right 锁死），"转向弱"是在**窄包络**里测的，不能外推为"完全不能转"。
- 部署合同与训练一致（tanh、5 Hz 滤波、55/2），**未发现合同漂移**（与 HIMLoco 不同）。

**R4 证据质量（`CONFIRMED`）**

- 训练交付的 `step_policy.onnx`（`04c86e7c…`）与上机的 jit/mu025 权重不同版本，比较时必须按 SHA 对齐；`ckpt["iter"]` 不可信（HIMLoco 侧已证实停在 16800）。

### 2.3 为什么 tanh 有效、摩擦对齐无效

- tanh + 抖动随机化作用于**动作平滑性**：符号翻转 30%→8.2%、roll 左倾消除。这是训练侧修好的问题。
- 摩擦对齐作用于**载荷尺度**：把仿真负载从 1/7 拉到 ≈实机，但**没有改变"转向靠踏步 + 轮无差速"的结构**，所以转向带宽不变；低摩擦下策略更保守，反而更弱（−0.026）。

### 2.4 尚未做的决定性实验（按成本）

| 优先级 | 实验 | 能排除什么 |
|---|---|---|
| **P0** | **单关节方向/零位核对**：固定站姿对单关节下 `+0.02 rad`、2 s、读 `q`，12 轴重复，与仿真同命令对符号 | 若出现符号相反的轴 → 转向弱直接由**部署映射**解释（与训练无关）；这是唯一能一票否决训练假设的实验 |
| P1 | 官方 `ai_free_walk` 偏航响应基准（同地面、同量级 wz 的 gyro_z 稳态值与调节时间） | "转向弱"是策略不足还是平台上限 |
| P1 | 接触几何单变量（轮半径/轮距/质心高度/接触刚度） | 后髋 2× 分布差是否可用接触解释 |
| P2 | 宽区间摩擦 DR（0.25–0.5）+ 在 μ=0.25 上从零训 | 低摩擦下是否存在可行步态 |

## 3. HIMLoco 的根因拆解

### 3.1 症状与数字

| 现象 | 数字 | 来源 |
|---|---|---|
| 零命令后腿下沉 | RL/RR calf `cmd−actual` **+0.336/+0.331**、thigh **+0.237/+0.239** rad（合计 ≈0.57 rad → 3–4 cm），7 s 内稳定 | `analysis/field-sink-per-axis.csv` |
| 零命令闭环 | A→B 交接通过（pose_error 0.202、quiet_dq 0.043）、PolicyWalk 零速、自动 Brake/ReturnStand/X，**0 安全告警** | `field/run-log-summary.md` |
| 推杆 | 反向 −0.30 m/s 可达、静差大；**掉头/横移未测** | session README |
| 静态 offset 补偿 | 后腿改善但 FR_thigh 过冲 **−0.305**、FL_calf 变差（0.006→0.142）、前倾+嗡鸣，2.2 s 后 X，已回退 0 | `analysis/field-sink-analysis.md` |
| Isaac 矩阵 | 72 试次 0 终止、0 非轮触地、最大 \|pitch\| 6.70° | `analysis/capability-matrix.md` |
| 同合同仿真复跑 | 后腿 `cmd−actual` 0.13–0.38 rad；**kp 55→85、kd 2→3.2 后 0.07–0.18**；pitch −9.2°→−5.3°（实机 −6.1°） | 本项目 RPT-008（MuJoCo 4.0.1，同合同包装） |

### 3.2 kp/kd 是不是"训练与部署不一致"——不是

| 审计项 | 训练 | 部署 | 判定 |
|---|---|---|---|
| 腿 PD | 55 / 2 | 55 / 2 | **一致** |
| 轮 PD | kp 0 / kd 2 | kp 0 / kd 2 | **一致** |
| 增益随机化 | reset 时 stiffness/damping × ±5% | 固定 55/2（分布中心） | 一致（分布内） |
| 控制器取值 | — | `motors.kp = config_.stiffness[i]` → yaml 55/2 | 按合同下发 |

来源：`docs/training-contract-audit.md`（PD 行 ✓）、`docs/field-bringup-checklist.md:119`、`docs/deployment-contract-18200.md:60`、`data/himloco_controller.cpp:356-364`、`common/environment.py:53-54`。

⇒ **"训练 kp/kd 与部署 kp/kd 不一致"不成立**。HIMLoco 的部署问题不是参数抄错，而是下面四层。

### 3.3 四层拆解

**L1 参数—负载层（主因，`CONFIRMED`）**：`q_actual ≈ q_cmd − τ_gravity/kp`。实机 0.336/0.331 rad；同合同仿真 0.13–0.38；kp85 后 0.07–0.18。静差 ≈ τ/kp，kp×1.55 → 静差 0.29–0.43×，方向一致。这是"参数与真实负载不匹配"。

**L2 训练集接触/载荷层（`OBSERVED`，交付方自述）**：`deployment-contract-18200.md:92` 与 `field-bringup-checklist.md:73` 写明"仿真俯仰比实机多约 7.5°，前髋力矩约为实机一半（3.7–5.1 vs 11–12 Nm）；**本策略在该静差下训练**"。⇒ 策略学到的重力补偿按仿真小负载标定；实机负载大 2 倍，同一 kp 下静差更大。归因到 **sim2real 静态接触/载荷差异**（点接触 vs 有限接触斑），不是 kp 抄错。

**L3 部署序列层（`INFERRED`，未实测）**：不同阶段用不同增益——本次 A 段 FixedStand 用 55；T15 站姿用 **85/3.2**；原厂 `ai_stand_up` **200/4**、`ai_free_walk` **40/1**；`deploy-drive-kp65.yaml` 是策略相位 **65** 候选（已构建、未执行）。而 handoff 只对**目标**做 `ramp_w=(k+1)/100`，**不平滑刚度**；若现场用 85/3.2 起站再按 B 切 55/2，就是"刚度阶跃 + 目标跳变"。**无实测记录 → `UNKNOWN`**。

**L4 合同细节层（`CONFIRMED`，已修/已知）**：handoff ramp 原本缺失（控制器第一步就下发 lerp 后目标 ≈0.1 rad，训练只给 1%），补齐后 `MAX_LEG_STEP` 0.1206→0.0582 rad、C++↔Python parity 1.19e-07；另有训练 DR 有 0/1 步延迟而部署 0、相位初值训练随机部署固定 0。这些解释"首帧冲击"，**不解释持续 0.33 rad 下沉**。

### 3.4 两个误修法

- **offset 补偿不行**：改几何不改刚度，后腿顶起来但前腿反向对抗（FR_thigh −0.305）、重心前移、力矩嗡鸣 → 操作员 2.2 s 后 X，offset 全退回 0。
- **kp85 不能从悬空推**：sim2real J/Q7 明令"悬空 kp 扫角只验证执行器，禁止据此给地面高 Kp 建议"。我们的 kp85 是**地面同合同** zero-B 仿真，只能算"地面 A/B 候选"，仍需实机地面 A/B。

### 3.5 证据质量问题（会推翻"仿真已通过"）

会话的 `mujoco-mujoco_eval.py` 调 `deploy_ref_controller.py`，其包装与 C++/`deploy.yaml` 不一致（腿差 **0.162 rad**、轮差 **10.95 rad/s**，零命令下轮目标 6.5×）。⇒ `mujoco-validated-20261121.mp4` 与"MuJoCo 前进 92%/后退 85%/转向 20%"**都不是同合同证据**；转向 20% 尤其不能作为能力证据。

## 4. "训练还是 sim2real"——逐条判定

| 判定项 | 结论 | 依据 |
|---|---|---|
| step 零命令抖动 | **训练问题**（动作参数化 + 抖动随机化）→ 已修 | 符号翻转 30%→8.2%；90%+ 动作维曾贴轨顶，tanh 后消失 |
| step 转向弱 | **训练/结构 + 训练域**：无轮差速、right 几何死结、门禁错配；摩擦对齐后未改善 | μ025 重训后 0.146 vs 0.199 |
| step right 门禁 FAIL | **不是能力问题**，是判据不可满足（eligible 掩码 + 几何裕度 0） | `calibration.json` 7/16 不可得分；15 臂无 RR 抬升 |
| HIMLoco 后腿下沉 | **部署参数 + 训练集载荷**：kp55 静差；策略在仿真小负载下训练 | 同合同 sim 复现；kp85 减半；交付方自述 3.7–5.1 vs 11–12 Nm |
| HIMLoco 重训必要性 | **无证据支持重训** | Isaac 72 试次 0 终止、0 非轮触地 |
| HIMLoco 转向 | **`UNKNOWN`** | 实机未测；MuJoCo 20% 来自漂移包装 |

## 6. 仍未知（需要新数据才能定案）

1. 实机四轮 Fn 真值与接触斑尺寸（决定 τ 与接触流形）；总重 26.0 vs 27.512 kg 的归属。
2. 实机横向力 Fy 的方向与量级（sim2real 判定的"唯一判别量"）。
3. 官方 `ai_free_walk` 的偏航响应基准（"转向弱"的参照）。
4. A→B 交界处是否真的存在增益阶跃（85/3.2 → 55/2）。
5. step 的单关节方向/零位是否与仿真一致（P0 未做）。
6. HIMLoco 的 9836 与 18200 是否动态等价（未做零更新对比）。
