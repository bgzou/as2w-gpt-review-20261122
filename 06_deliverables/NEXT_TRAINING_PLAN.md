## 3. 修订版排程（P0–P7）

### P0 身份与部署冻结（0.5 天，0 训练）

- 权重 SHA（含 `45b36`/`99995126`/`a3215` 区分）、训练代码提交号、USD/MJCF 哈希、运行参数实际读回。
- **12 轴单关节方向/零位核对**：固定站姿，单轴 `+0.02 rad`、2 s、读 `q`，12 轴逐一，与仿真同命令对符号（解决 hip sign −1/+1 的表述冲突）。
- 轮轴符号与轮速方向；旧权重回退路径。

**出口**：全部权重/配置可唯一追溯；12/12 轴方向正确。

### P1 实机物理测量（1–2 天）

1. 四轮同时称重（FL/FR/RL/RR 法向力）。
2. 整机称重（判定 26.0 kg vs 27.512 kg；`27.012` 只是资产变体，不能替代称重）。
3. 整机 CoM（x/y/z）。
4. 轮径、受载半径、轮距、轮心高度、外倾角。
5. 接触斑（压敏膜/压力纸）与轮胎压缩。
6. 静摩擦、动摩擦、滚动阻力、横向滑移阻力、**左右轮 Fy 方向**。

**出口**：得到可用于仿真建模的真实参数范围（含不确定度）。

### P2 仿真物理校准（1–2 天）

- 修复轮心/接触几何；验证 `impratio`、`condim`、`solref`、`solimp`、`dt`、迭代次数。
- 分指标复现：pitch、四轮 Fn、后腿 q、前后髋力矩；**前髋力矩缺口必须书面声明**。
- W_A 只作**候选相对对照**；不得为匹配单一指标把 impratio 调到极端。
- 有限接触斑只做**结构敏感性**（刚性圆柱 vs 有限接触区域），不得宣称"证明根因"。

**出口**：pitch ±0.3°、Fn ±5%、后腿 q ±0.07 rad；前髋力矩差异有明确记录。

### P3 部署合同与第二仿真器（0.5–1 天）

- C++/Python/ONNX 同一份 ≥60 帧夹具逐帧对比（tanh、0.6 增益、轮 ff、滤波、100 步 ramp、历史栈）。
- MuJoCo 换成 C++ 合同包装后再作为第二仿真器。
- `t3_3` 的独立同合同结果可作对照，**不能替代** C++ 执行链验证。

**出口**：逐帧最大误差 ≤ 预注册浮点容差；parity 链可复现。

### P4 奖励/门禁修复（0.5–1 天）

- 修 `calibration.json` 7/16 eligibility；每个 gate 判据必须对应一个奖励项/可观测项。
- right 改 skating：允许 RR 持续滚动接触；禁止非轮部件接地；侧向速度方向正确；不持续失控横滑；姿态/轮载稳定。
- 建立**官方 `ai_free_walk` 偏航基准**（同地面、同量级 wz 的 gyro_z 稳态与调节时间）。

**出口**：16 组合资格/事件/统计定义一致；right 判据物理可达；官方基准入库。

### P5 短程诊断训练（按 GPU，100–200 更新/支线）

- **v2-step**：以 `99995126`（jit）与 `a3215`（mu025）为双基准；每条支线一次只改一个因素；每 100 更新回归全部旧场景（零命令抖动、四方向踏步、yaw、RR 支撑、低摩擦退化）。
- **HIMLoco**：先做 **18200 vs 9836 零更新同场景对比**；未满足 Phase J 五条件前不启动正式 PPO。
- 记录：original/filtered/applied 目标、q/dq、τ、四轮 Fn、pitch/roll、tilt 余量。

**出口**：每桶出表；任一桶退化即回退。

### P6 正式训练（仅 P5 通过后）

- 4096 env × 48 steps = 196,608 env-steps/更新；600 更新 ≈ 1.18 亿 env-steps（约 44 min/级，实测为准）。
- 关键配置至少 3 个独立 seed；**不得把三个 checkpoint 的单项成绩拼成一个"全通过"**。

### P7 冻结与部署（顺序不可跳）

Isaac/PhysX 验收 → MuJoCo 同合同 → ONNX 逐帧 parity → CPRO ARM64 CTest → 实机只读 → 零命令接管 → 有界低速 → 扩大包络。任一步失败，回退到上一份**完整通过**的权重。

1. 整机质量、CoM、四轮 Fn、接触几何已测。
2. 真实摩擦与接触斑有数据或明确不确定范围。
3. 12 轴方向/零位通过核验。
4. 仿真接触模型复现关键静态指标（pitch/Fn/后腿 q）。
5. unified_dr 奖励资格与 gate 已修复。
6. right 验收目标已改 skating。
7. 官方偏航基准已建立。
8. 两条线父权重已定（v2-step：jit/mu025 双基准；HIMLoco：18200 现场基准，9836 待文件）。
9. C++/Python/第二仿真器合同一致。

**现状：0/9 满足。** 对 HIMLoco，Phase J 五条件仍全不满足 → 不允许正式续训；对 v2-step，完成 P0–P4 后才允许 100–200 更新诊断训练。

## 6. 若照原计划直接训练的风险

1. 继承错误接触模型 → 策略学错负载分配（前髋 7.2 Nm 缺口）。
2. 奖励/门禁不修 → 训练永远满足不了验收（7/16 不可得分）。
3. 继续要求 RR 抬升 → 在不可行目标上烧预算。
4. 直接换 9836 → 丢失 18200 的实机参考。
5. 用旧 MuJoCo 包装 → 把控制合同错误当动力学结果。
6. 直接加 kp → 实机过载/振荡风险（未做地面 A/B）。
7. 只追回报 → 某方向变好、另一方向退化。

## 7. 如果只做五件事

1. **四轮称重 + 整机 CoM**（判 26.0 vs 27.512）。
2. **接触斑 + 摩擦 + Fy 方向**（让接触模型有物理依据）。
3. **12 轴方向/零位核对**（排除部署映射；解决 hip sign 冲突）。
4. **HIMLoco 18200/9836 零更新对比 + 修 MuJoCo 包装**。
5. **修门禁 + right 改 skating + 官方偏航基准**。
