# 下一轮训练该怎么排（v3，2026-11-22）

> 写给没看过项目文件的人。先说清"同事的计划是什么、我们的意见是什么"，再给可执行的步骤和判定标准。出处集中在最后一节。

---

## 0. 一页看懂

**同事的计划（`任务书.md`）**：保留两条训练线（v2-step 与 HIMLoco），各自沿用原来的训练代码、观测和动作合同；先做"无策略静站 + 父权重回放"，然后分 S1–S5 阶段训练：先在平地练站立/前后/侧移/转向，再练缓坡，最后冻结部署。资产方面使用 T2 v2 的 URDF，并做两档摩擦（0.25 和 0.50）的对照。

**我们的判断**：**方向对，顺序错，有两处内容要改。**

- **方向对**：先看资产/接触、再做训练；按命令分段设奖励；不允许"穿地换姿态"——这些都对。
- **顺序错**：它把"开训"排在"测重量/质心/接触斑/摩擦"之前。现在是"还不知道机器人到底多重、四轮各承多少、地面多滑"就要训 600 轮，训完也无法解释结果。
- **内容要改**：① 它要求"右移时四个轮子都能抬起"，但几何上右后轮抬不起来（见根因报告 2.3）；② 它只调"摩擦系数"，但真正影响仿真静态力矩的是接触求解器的"摩擦阻抗"和接触斑形状，不是 μ 数值本身。
- **两条线要分开**：v2-step 可以走"短程诊断训练"；HIMLoco **先别训**，它的现场问题不是策略能力，是站姿增益和载荷口径。

**一句话**：**先花 3–4 天把"能测量的"测完，再花 1 天把门禁修对，然后才轮到 100–200 轮的短程诊断训练；600 轮以上的正式训练要等这些全部通过。**

## 2. 我们的意见（按重要性）

### 2.1 顺序问题：测量必须在训练之前

**为什么**：训练的目标是让策略"在仿真里学会在实机上能用"。如果仿真里的机器人重量、四轮受力、地面摩擦、接触形状和实机不一样，策略学到的就是"另一个世界"的用法。训完再到实机上发现不对，只能推倒重来——600 轮约 1.18 亿环境步，不是小钱。

**具体缺什么**：
1. 整机到底多重？现在有两套资产：**26.0 kg**（官方 URDF）和 **27.512 kg**（load-v0）。两者 base 质量差 1 kg、质心前后差 15 mm。仅这一项就能改变站立时的腿差（我们做过：base +1 kg 会让后腿差从 0.378 变 0.424 rad）。
2. 四个轮子各承多少？现在实机的 48/48/80/80 N 是**反演**出来的，不是称出来的。
3. 地面多滑？训练用 0.5，实机估计 0.25，但 0.25 也是估计。
4. 轮胎接触是"点"还是"面"？仿真里轮子是圆柱，和地面是**单点接触**；真实轮胎一定有一个压扁的接触斑。
5. 12 个腿轴的方向和零位对不对？现场标定记录 hip 符号是 −1，后期表述是 +1，没有统一核对。

### 2.2 目标问题：右移的"四轮抬升"做不到

**事实**：抬起右后轮后，剩下的支撑点是左前、右前、左后，它们组成的三角形有一条边正好穿过重心投影——静态稳定裕度是 0。15 条训练臂 + 15 mm 配重都没有让右后轮抬起过一次。

**建议**：右移改成"滑移（skating）"验收——允许右后轮一直贴地滚动，只要求：不摔、不出现非轮部件触地、侧移方向正确、不持续横滑、姿态和轮载稳定。将来如果改了轮距/质心，再重新评估"抬轮"是否可行。

### 2.3 接触模型：只调 μ 不够

**事实**：在 MuJoCo 的静态实验里，把"摩擦约束阻抗"（`impratio`，一个求解器参数）从 1 调到 100，前髋力矩从 **−4.61 变到 −11.47 Nm**（实机 −11.81）；而把物理摩擦系数 μ 从 0.8 调到 1.0，力矩只变 **≤0.3 Nm**。

**含义**：真正决定"仿真静力矩像不像实机"的是**接触怎么解**（单点还是面、阻抗多大、接触刚度/阻尼），不是 μ 的数值。只对齐 μ，很可能"静态负载看起来对了，但横向力和转向还是不对"。

**建议**：接触模型验收要同时记录 `μ / impratio / condim / solref / solimp / 接触几何 / 时间步`，并且**多指标联合**（pitch、四轮 Fn、后腿角、前后髋力矩）。不能用"把 impratio 调到某个值让某一个力矩对上"来宣称"接触模型已验证"。

### 2.4 两条补充：HIMLoco 的父权重与俯仰项

- **父权重**：现场唯一验证过的是 `model_18200`（11-20 18:03–18:42）。9836 与 13900 从未上机。用 9836 续训，等于把"有现场证据的版本"换成"更早、没上过机的版本"。建议：**先把 18200 和 9836 做零更新同场景对比**，再决定父权重；9836 连文件/SHA 都要先补齐。
- **俯仰项 B**：它的 A/B 数据是——低摩擦持续前倾 6/48→0/48，但高摩擦接管后仰仍有 29/48，停车位移 P95 从 14.6 增到 16.5 cm。**它修的是"运动中的持续前倾"，不是现场的"后腿静差"**；而且有停车变差的代价。建议先做**地面 kp 55 vs 85 的站姿 A/B**（记录目标−实际），俯仰项要做就预注册"停车退化 ≤10%"。

### 2.5 顺带修正：轮差速不是问题

任务书要求"纯侧移/转向时轮速指令为零"。这**不是缺陷**——宇树官方 AS2-W 的转向就是靠腿踏步，不靠轮差速。真正的问题是：既然只走踏步，就需要一个"官方踏步能转多快"的基准，否则"转向弱"没有参照。建议用官方 `ai_free_walk` 的偏航响应做基准。

## 3. 建议的做事顺序（P0–P7）

### P0 冻结身份（0.5 天，不训练）

**做什么**：把每份权重的 SHA、训练代码提交号、资产（URDF/MJCF/USD）哈希、实际运行参数全部记录；把 12 个腿轴的单关节方向/零位核对一遍（固定站姿，单轴 `+0.02 rad`，保持 2 s，看实际角往哪边动，12 轴各一次，和仿真同命令对比）。

**为什么**：后面所有讨论都要先回答"你说的是哪份权重、哪个资产"。单关节核对是最便宜、也最可能一票否决"训练假设"的实验——如果某个轴方向相反，"转向弱"就是部署映射问题，和训练无关。

**怎么算过**：12/12 轴方向正确；每份权重/资产能唯一追溯；有旧权重回退路径。

### P1 实机物理测量（1–2 天）

**做什么**：
1. 四轮同时称重（每轮下的法向力），以及整机重量；
2. 整机质心（前后/左右/高度）；
3. 轮径、受载半径、轮距、轮心高度、外倾角；
4. 轮胎接触斑（压敏膜/压力纸）和压缩量；
5. 静摩擦、动摩擦、滚动阻力、横向滑移阻力、左右轮横向力方向。

**为什么**：这些是仿真模型的输入。没有它们，"两档摩擦"只是两个猜测。

**怎么算过**：得到可用于建模的参数范围（含不确定度）；总重能判定 26.0 还是 27.512 kg。

### P2 仿真校准（1–2 天）

**做什么**：按 P1 的实测改仿真（接触几何、`impratio/condim/solref/solimp`、时间步），然后分指标复现：pitch、四轮 Fn、后腿关节角、前后髋力矩。

**为什么**：只有仿真能复现实机的静态姿态和负载分配，训练才有意义。

**怎么算过**：pitch 误差 ≤0.3°、Fn 误差 ≤5%、后腿角误差 ≤0.07 rad；**前髋力矩的缺口必须书面写出来**，不能假装通过。

### P3 合同与第二仿真器（0.5–1 天）

**做什么**：用同一份 ≥60 帧的输入夹具，让 C++ 控制器、Python 参考、ONNX、MuJoCo 逐帧对齐（tanh、0.6 增益、轮前馈、滤波、100 步交接、历史栈）。

**为什么**：现场那次"MuJoCo 验证通过"用的 Python 包装和真正部署的 C++ 不一致（腿差 0.16 rad、轮差 10.9 rad/s），所以那条证据无效。第二仿真器必须先对齐合同，否则"仿真说行"没有意义。

**怎么算过**：逐帧最大误差在预注册的浮点容差内。

### P4 修门禁与基准（0.5–1 天）

**做什么**：
1. 修 `unified_dr` 的资格掩码（7/16 不可得分），保证每个门禁判据都对应一个奖励项或可观测项；
2. 右移改"滑移"验收；
3. 测官方 `ai_free_walk` 的偏航响应，作为"转向应该多快"的基准；
4. 明确"三轮支撑"的统计窗口（例如 1 s 内占比 <5%）。

**为什么**：不修门禁，训练永远满足不了一个不可能的条件；没有官方基准，"转向弱"永远说不清。

**怎么算过**：16 个组合的资格/事件/统计定义一致；右移判据物理可达；官方基准入库。

### P5 短程诊断训练（按 GPU，每条支线 100–200 轮）

**做什么**：
- v2-step：以**实机上过的两版权重**（jit `99995126`、mu025 `a3215`）为基准，每条支线只改一个因素，每 100 轮把所有旧场景回归一遍（零命令抖动、四方向踏步、转向、右后轮支撑、低摩擦退化）。
- HIMLoco：先做 **18200 vs 9836 零更新对比**；在"仿真基准可信 + 载荷口径对齐"之前，不启动正式 PPO。

**为什么**：用真实上机权重当基准，才能把"训练改动"和"版本差异"分开。

**怎么算过**：每个场景出一张表；任何一项退化就回退。

### P6 正式训练（只在 P5 通过后）

**做什么**：按 S1→S4 走，关键配置至少 3 个独立 seed；600 轮 ≈ 1.18 亿环境步（4096 环境 × 48 步 × 600），约 44 分钟一级（以实际日志为准）。

**注意**：**不能把三个不同 checkpoint 的单项好成绩拼成一个"全通过"**——这是以前踩过的坑。

### P7 冻结与部署

**顺序**：Isaac/PhysX 验收 → MuJoCo 同合同验收 → ONNX 逐帧对比 → CPRO ARM64 编译/测试 → 实机只读 → 零命令接管 → 有界低速 → 扩大范围。任何一步失败，回退到上一份**完整通过**的权重。

## 4. 验收标准（建议值，不是历史成绩）

| 指标 | 通过 | 回退 | 为什么这么定 |
|---|---|---|---|
| 12 轴方向 | 12/12 正确 | 任一轴反向 | 方向反了，后面全白搭 |
| 零命令翻转率 | <10% | >15% | 现场能听到/摸到的抖动主要是这个；旧版 30%，jit 8.2%，mu025 12.85% |
| 腿目标峰峰值 | <0.30 rad | >0.40 rad | 现在 0.36–0.37，目标是把幅度压下来 |
| 转向斜率 | ≥ 官方基准×0.70 | <0.50 | 现在 0.15–0.20；官方基准待测 |
| 侧移有效响应 | ≥50% 且方向正确 | <20% 或反向 | mu025 出现方向反了（−1.14） |
| 持续三轮支撑 | <5%（1 s 窗） | >15% | 正常步态允许短时卸载，不允许长期三轮 |
| HIMLoco 后腿静差（kp55） | <0.15 rad | >0.20 rad | 现实机 0.33；kp85 仿真 0.07–0.18 |
| 停车位移 P95 | ≤基线×1.10 | >基线×1.20 | 俯仰项 B 会把它从 14.6 推到 16.5 cm，必须设上限 |
| 仿真 Fn 相对实测 | <5% | 超差 | 负载分配对了，训练才有意义 |
| pitch / 后腿角 | ≤0.3° / ≤0.07 rad | 超差 | 与现有仿真基准的容差一致 |

## 5. 什么情况下才允许开训（九条全满足）

1. 整机重量、质心、四轮 Fn、轮几何已测；
2. 真实摩擦与接触斑有数据或明确不确定范围；
3. 12 轴方向/零位通过；
4. 仿真能复现 pitch、Fn、后腿角；
5. `unified_dr` 的奖励资格与门禁已修；
6. 右移验收已改"滑移"；
7. 官方踏步偏航基准已建立；
8. 两条线父权重已定（v2-step：jit/mu025 双基准；HIMLoco：18200 现场基准，9836 待文件）；
9. C++/Python/第二仿真器合同一致。

**现状：0/9。** 对 HIMLoco，Phase J 的五个重训条件也仍全不满足。

## 6. 如果硬按原计划直接训，会发生什么

1. **把错误的负载分配学进策略**：仿真前髋力矩只有实机一半，策略会按"轻机器人"的方式站立和迈步。
2. **在不可能的门禁上烧预算**：右后轮抬升 + 7/16 不可得分，训练再久也过不了。
3. **把版本差异当成训练效果**：换 9836 当父权重，会和 18200 的现场结果不可比。
4. **把控制合同错误当成动力学结论**：旧 MuJoCo 包装不一致，"仿真通过"是假的。
5. **只追回报**：某一方向变好、另一方向退化（以前出现过）。

---

## 7. 如果只做五件事

1. **四轮称重 + 整机质心**（判定 26.0 还是 27.512 kg）。
2. **接触斑 + 摩擦 + 横向力方向**（让接触模型有物理依据）。
3. **12 轴方向/零位核对**（排除部署映射；解决 hip 符号 −1/+1 的冲突）。
4. **HIMLoco 18200 vs 9836 对比 + 修 MuJoCo 包装**。
5. **修门禁 + 右移改滑移 + 官方偏航基准**。
