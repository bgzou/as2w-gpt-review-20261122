## 0. 一页看懂

**同事的计划**：保留两条训练线（v2-step 与 HIMLoco），各自沿用原训练代码/观测/动作合同；先做"无策略静站 + 父权重零更新回放"（S0），再分 S1–S5 训练（平地站立/前后/侧移/转向 → 缓坡 → 单因素诊断 → 联合随机化 → 冻结部署）；资产用 T2 v2 URDF，做两档摩擦（0.25 / 0.50）对照；HIMLoco 父权重用 9836（13900 停车对照、10436 验俯仰项）。

**我们的判断**：**方向对，顺序错，两处内容要改，一条线要缓。**

- **方向对**：先看资产/接触再训练、按命令分段奖励、禁止"穿地换姿态"、保留父权重与全部验收数据——都对。
- **顺序错**：它把"开训"（S1，100–600 轮）排在"测重量/质心/接触斑/摩擦/12 轴方向"之前。现在连机器人多重、四轮各承多少、地面多滑都不知道，训完无法解释结果。
- **内容要改**：① 右移要求"四轮抬升"几何上做不到（右后轮抬起后静态裕度 0）；② 只调 μ 不够——真正影响仿真静态力矩的是接触求解器的阻抗与接触斑，不是 μ 数值。
- **一条线要缓**：HIMLoco 的现场问题不是策略能力，是站姿增益（kp55）与训练载荷口径；先把这两件解决，再谈训练。

**一句话**：**先花 3–4 天把能测的测完、1 天把门禁修对，再做 100–200 轮短程诊断；600 轮以上的正式训练等九条门槛全部通过。**

## 3. 我们的六条意见（带理由与数字）

### 3.1 顺序：测量必须在训练之前

**为什么**：训练是让策略"在仿真里学会实机上能用"。如果仿真的重量、四轮受力、摩擦、接触形状与实机不同，策略学的是另一个世界。训完再发现不对，600 轮 ≈ 1.18 亿环境步就浪费了。

**必须补的测量**：
1. 整机重量（判 **26.0 kg** 官方 URDF vs **27.512 kg** load-v0；两者 base 差 1 kg、质心前后差 15 mm；仅 base +1 kg 就能让后腿静差 0.378→0.424 rad）。
2. 四轮独立 Fn（现在 48/48/80/80 N 是**反演**，不是称重）。
3. 真实摩擦（0.25 是估计）。
4. 接触斑/轮胎压缩（仿真里是单点接触）。
5. 12 轴方向/零位（现场 hip 符号 −1 vs 重力锚定 +1 未对齐）。

### 3.2 目标：右移的"四轮抬升"做不到

见 §2.2 第 7 条。建议右移改 **skating**：允许 RR 持续滚动接触；禁止非轮部件接地；侧向速度方向正确；不持续失控横滑；姿态/轮载稳定；其余三轮按合理时序卸载/支撑。若将来改轮距/质心，再评估抬轮。

### 3.3 接触模型：只调 μ 不够

`impratio` 一阶、μ 二阶；且 W_A 与 W_D 由**互斥**的 impratio 主导（W_A 匹配 pitch/Fn/后腿，W_D 匹配前髋），**"双锚点不可兼得"**。验收要同时记录 `μ / impratio / condim / solref / solimp / 接触几何 / 时间步`，多指标联合（pitch、四轮 Fn、后腿角、前后髋力矩）。**不能用"调 impratio 让某一个力矩对上"来宣称接触模型已验证。**

### 3.4 HIMLoco 父权重：先 18200 vs 9836

9836/13900 从未上机，9836/10436 连文件与 SHA 都没有。以 9836 为父 = 把"有现场证据的链"换成"更早、未上机的检查点"；若两者动态表现差异明显，18200 的现场结论不能平移，要重做 S0–S3。**先做零更新同场景对比，再决定父权重。**

### 3.5 HIMLoco 俯仰项：修的不是现场问题

俯仰项 B 的数据来自"低摩擦运动前倾 / 高摩擦接管后仰"（DR 场景的持续姿态），而现场主诉是**推杆时后腿静差 0.33 rad / −6.1° pitch**，力学是 `τ_gravity/kp`——**加俯仰奖励不改变静差**。且 B 有代价（停车 P95 +13%）。建议：先做**地面 kp 55 vs 85 站姿 A/B**（记录 `cmd−actual`）；俯仰项要做就预注册"停车退化 ≤10% + 三轮支撑"。

### 3.6 轮差速：不是问题，但要基准

任务书"纯 vy/wz 轮速为零"与宇树官方一致，**不是缺陷**。真正缺的是参照：建议用官方 `ai_free_walk` 的偏航响应（同地面、同量级 wz 下 gyro_z 稳态与调节时间）作为"转向应该多快"的基准；现在 yaw 斜率 0.146–0.199，没有基准就说不清是策略弱还是平台上限。

## 4. 修订排程 P0–P7

### P0 身份冻结（0.5 天，0 训练）

**做什么**：权重 SHA、训练代码提交号、资产（URDF/MJCF/USD）哈希、运行参数实际读回；**12 轴单关节方向/零位核对**（固定站姿，单轴 `+0.02 rad`、2 s、读 `q`，12 轴逐一，与仿真同命令对符号）；轮轴符号/轮速方向；旧权重回退路径。

**为什么**：后面所有讨论先要回答"哪份权重、哪个资产"；单关节核对最便宜、且可能一票否决"训练假设"（若某轴反向，转向弱=部署映射问题）。

**出口**：12/12 轴方向正确；权重/配置唯一可追溯。

### P1 实机物理测量（1–2 天）

**做什么**：四轮同时称重（FL/FR/RL/RR）；整机重量；整机 CoM（x/y/z）；轮径/受载半径/轮距/轮心高度/外倾角；接触斑（压敏膜/压力纸）与轮胎压缩；静摩擦/动摩擦/滚动阻力/横向滑移阻力/左右轮 Fy 方向。

**为什么**：这些是仿真模型的输入；没有它们"两档摩擦"只是两个猜测。

**出口**：参数范围（含不确定度）；总重能判 26.0 还是 27.512 kg。

### P2 仿真物理校准（1–2 天）

**做什么**：按 P1 改接触几何、`impratio/condim/solref/solimp`、时间步；分指标复现 pitch、四轮 Fn、后腿 q、前后髋力矩；W_A 只作候选相对对照；有限接触斑只做结构敏感性（刚性圆柱 vs 有限接触区域）。

**为什么**：仿真能复现实机静态姿态与负载分配，训练才有意义。

**出口**：pitch ≤0.3°、Fn ≤5%、后腿 q ≤0.07 rad；前髋力矩缺口**书面声明**（不可假装通过）。

### P3 合同与第二仿真器（0.5–1 天）

**做什么**：同一份 ≥60 帧夹具，C++ / Python / ONNX / MuJoCo 逐帧对齐（tanh、0.6 增益、轮前馈、滤波、100 步 ramp、历史栈）。MuJoCo 换成 C++ 合同包装后再作第二仿真器；`t3_3` 的独立结果可作对照，但不能替代 C++ 执行链。

**为什么**：旧 MuJoCo 包装漂移 0.1616 rad / 10.9488 rad/s，"仿真通过"无效。

**出口**：逐帧最大误差 ≤ 预注册浮点容差。

### P4 修门禁与建基准（0.5–1 天）

**做什么**：修 `calibration.json` 7/16 eligibility（每个 gate 判据对应一个奖励项/可观测项）；右移改 skating；测官方 `ai_free_walk` 偏航基准；明确三轮支撑窗口（1 s 内占比 <5%）。

**为什么**：不修门禁，训练永远满足不了验收；没有官方基准，"转向弱"无法判定。

**出口**：16 组合资格/事件/统计一致；右移判据物理可达；官方基准入库。

### P5 短程诊断训练（按 GPU，每条支线 100–200 轮）

**v2-step**：以 `99995126`（jit）与 `a3215`（mu025）双基准；每条支线只改一个因素；每 100 轮回归全部旧场景（零命令抖动、四方向踏步、转向、RR 支撑、低摩擦退化）；记录 original/filtered/applied 目标、q/dq、τ、四轮 Fn、pitch/roll。

**HIMLoco**：先做 **18200 vs 9836 零更新同场景对比**；未满足 Phase J 五条件前不启动正式 PPO；地面 kp 55 vs 85（仅站姿）A/B，记录 `cmd−actual`。

**出口**：每桶出表；任一桶退化即回退。

### P6 正式训练（仅 P5 通过后）

4096 env × 48 steps = **196,608 env-steps/更新**；600 更新 ≈ **1.18 亿 env-steps**（约 44 min/级，以日志为准）；关键配置**至少 3 个独立 seed**；**不能把三个 checkpoint 的单项成绩拼成一个"全通过"**。

### P7 冻结与部署（顺序不可跳）

Isaac/PhysX 验收 → MuJoCo 同合同 → ONNX 逐帧 parity → CPRO ARM64 CTest → 实机只读 → 零命令接管 → 有界低速 → 扩大包络。任一步失败，回退上一份**完整通过**的权重。

## 6. 开训门槛（九条全满足）

1. 整机重量、CoM、四轮 Fn、轮几何已测；
2. 真实摩擦与接触斑有数据或明确不确定范围；
3. 12 轴方向/零位通过；
4. 仿真复现 pitch/Fn/后腿 q；
5. `unified_dr` 奖励资格与门禁已修；
6. 右移验收改 skating；
7. 官方踏步偏航基准已建立；
8. 两条线父权重已定（v2-step：jit/mu025 双基准；HIMLoco：18200 现场基准，9836 待文件）；
9. C++/Python/第二仿真器合同一致。

**现状：0/9。** 对 HIMLoco，Phase J 五条件（根因可补偿层、基准可信、DR 可覆盖、奖励可验证、成本收益）也仍全不满足。

## 7. 硬按原计划训的风险

1. **继承错误接触模型**：仿真前髋力矩只有实机一半，策略学"轻机器人"的站立/迈步。
2. **在不可能门禁上烧预算**：右后轮抬升 + 7/16 不可得分。
3. **版本差异被当成训练效果**：换 9836 后与 18200 现场结果不可比。
4. **把控制合同错误当动力学结论**：旧 MuJoCo 包装不一致。
5. **直接加 kp 的实机风险**：未做地面 A/B 就提高 kp，可能过载/振荡。
6. **只追回报**：某方向变好、另一方向退化（历史出现过）。

## 8. 如果只做五件事

1. **四轮称重 + 整机 CoM**（判 26.0 vs 27.512）。
