为什么"调权重"经常没效果？

训练日志里的真实量级（每步未加权）：

塑形项只有跟踪项的 1% 量级。提权 5 倍仍在同量级 → 先改结构（门控/事件/覆盖），再改权重；一次只改一项。

奖励与门禁必须对齐（反面案例）

unified_dr 的 calibration.json 用 eligible 掩码把 7/16 个"方向×轮"组合标成不可得分：

  • left 缺 RR；right 缺 RL；yaw_left 只 RR；yaw_right 只 FR/RL
  • 而验收要求四轮各 ≥2 次抬轮 → 结构性不可能通过
  • 结果：DR 三阶段全部 qualified=false（失败项 32/33/31），不是训练不够
新任务规则：门禁的每个判据都要映射到至少一个奖励项/可观测项，映射不到就不许开门禁。

域随机化：串行还是并行？

答案：阶段串行 · 环境内并行 · 回合级独立采样
参数DR0 标称DR1 接触/载荷DR2 +噪声/延迟/抖动DR3 +外部推扰采样时机

① 阶段串行（会话级）

DR1 → DR2 → DR3 是三次独立训练会话，DR2 含 DR1，DR3 含 DR1+DR2。每级 600 更新，结束后固定回放筛选，再启动下一级。

② 环境内并行（更新级）

同一级里 4096 个环境同时训练，每个环境各自采样自己的摩擦/质量/延迟/增益。一个更新里就同时覆盖大量域组合。

③ 回合级独立（reset 级）

每个环境 reset 时重采"每回合"参数（增益/偏置/延迟/抖动）；startup 参数（摩擦/质量/COM）整个训练固定。

同一时刻，64 个环境拿到 64 套不同的摩擦/质量/偏置/延迟组合——这就是"环境内并行"的含义。

怎么保证"抗所有随机化"的能力

摩擦 DR 必须修正（历史最大缺口）

历史区间 0.5–1.0 高于标称 0.5，而实机是 0.25 → 实机工况从未被训练覆盖。

建议改成：

"contact": {
  "static_friction":  [0.25, 0.50],
  "dynamic_friction": [0.18, 0.35]
}

并用 as2w-t2-v2-mu025.usd（地面 μ=0.25 + min 合并）作标称资产，先固定 μ=0.25 重训，再扩区间。
