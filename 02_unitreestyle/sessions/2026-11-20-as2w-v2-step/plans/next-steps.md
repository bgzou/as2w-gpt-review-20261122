# 下一步计划（2026-11-20 会话末）

## 0. 当前结论与未决问题

已确认：

1. tanh + 5 Hz + 抖动随机化 → 实机零命令抖动下降（翻转率 30%→8–13%），姿态偏置改善（roll 左倾消除）。
2. 仿真摩擦 0.5 与实机 0.25 不匹配，导致仿真静态髋负载只有实机的 1/7–1/14。
3. **但摩擦对齐后重训的权重，实机转向没有改善（0.146 vs 0.199）** → 转向弱的根因不在训练摩擦。

未决：为什么实机转向/侧移几乎不动，而仿真里同样的权重可以做到 4/4 抬轮 + 跟踪 1.0。

## 1. 优先级 P0：单关节命令方向与执行核对（不需要整机行走）

目的：排除"实机 LowCmd 方向/零位与仿真不一致"这一最便宜的假设。

方法（每次单轴、小幅度、须现场当次同意）：

1. 固定站姿态下接管，对单个腿关节下发 `+0.02 rad` 目标偏移，保持 2 s，读 LowState 的实测 `q`。
2. 对 12 个腿轴重复，记录"命令方向 → 实测方向"符号表。
3. 与仿真同一命令下的 `q` 变化方向逐轴对比。
4. 判定：若出现符号相反的轴，转向弱就直接得到解释（部署映射问题，训练无关）。

## 2. P1：曲线与指标监控清单（每次训练/试验都要看）

**训练侧（`reward-components.jsonl`）**

- `executed_signflip_fraction`（目标翻转率，越低越稳）
- `executed_delta_mean`（每步动作增量）
- `executed_abs_mean`（饱和程度，靠近 1 说明在打满）
- `event_{mode}_{wheel}`（各方向各轮抬落事件）
- `support_{mode}_{wheel}`（各轮承重比例）
- `swing_event` / `swing_coverage`

**门禁侧（每 200 轮）**

- 四方向 `wheels_with_2plus_events`（目标 4/4，right 目前恒为 2–3/4）
- `tracking_ratio_min`、`tilt_p95_deg`、`falls`

**实机侧（每次会话）**

- yaw 跟踪斜率（实测 gyro_z / 指令 wz，回归）
- 侧移：机体世界系加速度积分方向 vs 指令 vy
- 目标 p2p、翻转率、跟踪误差、roll/pitch 均值与极值
- 保护流计数（`motorstate_or`、`warning_or`、dropped 行数）

## 3. P1：转向弱的其他候选（按成本排序）

1. **轮速差速**：当前轮速只由 vx 驱动，转向完全靠踏步。可评估"部署侧 wz 差速"作为新版本（偏离训练合同，需要单独评审 + 实机分阶段验证）。
2. **接触几何**：轮胎接触面/半径、轮距、质心高度；MuJoCo 里同样差约 2 倍，指向接触模型而非训练奖励。
3. **策略转向机制**：仿真里 4 轮抬落产生偏航力矩，实机可能因轮胎打滑无法产生；可做"抬轮瞬间的机体角加速度"对比验证。

## 4. P2：摩擦 DR 区间修正（暂缓，等 P0 结论）

当前 `domain_config.json` 的摩擦随机化区间是 0.5–1.0（比标称 0.5 更高），实机 0.25 从未被覆盖。
若后续仍要做 DR，应改为 `dynamic 0.18–0.35 / static 0.25–0.5`。
但鉴于"固定 0.25 重训并没有改善实机转向"，**先做 P0 再决定是否值得投入宽区间 DR**。
