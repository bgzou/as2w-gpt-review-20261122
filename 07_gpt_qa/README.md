# 07_gpt_qa — 与网页版 GPT 的问答回路

这个文件夹是为了让**网页版 GPT**（只能读、不能跑代码/写仓库）和**本地执行侧**（能跑仿真、能读全部原始数据）配合工作而设的。
目标不是"让 GPT 猜"，而是：**GPT 提问 → 人把问题贴回来 → 执行侧用原始数据回答（并注明需要新实验的项）→ GPT 基于答案继续给指导。**

## 目录与文件

| 文件 | 谁写 | 作用 |
|---|---|---|
| `README.md` | 执行侧 | 本协议（当前文件） |
| `AVAILABLE_DATA.md` | 执行侧 | **数据目录**：仓库里有什么、没什么、哪些是权威口径 |
| `QUESTIONS_TEMPLATE.md` | 执行侧 | GPT 提问必须用的格式（复制到对话里） |
| `ANSWERS_ROUND_0.md` | 执行侧 | 第 0 轮：对"最可能被问到的 6 个问题"的预先回答 |
| `QUESTIONS_ROUND_n.md` | 人（贴 GPT 的问题） | 第 n 轮问题清单 |
| `ANSWERS_ROUND_n.md` | 执行侧 | 第 n 轮回答（带证据路径；需新实验的标 `NEEDS_EXPERIMENT` + 成本） |

## 回路怎么跑

1. GPT 读完任务书/初稿后，用 `QUESTIONS_TEMPLATE.md` 的格式提问（每问带 id、为什么需要、已读文件、期望的回答形式）。
2. 人把问题原文贴进 `QUESTIONS_ROUND_n.md`（无需改写），告诉执行侧"第 n 轮"。
3. 执行侧写 `ANSWERS_ROUND_n.md`：能用现有数据回答的直接给数字+路径；不能的写 `NEEDS_EXPERIMENT`（做法、成本、能排除什么）。
4. 人把 `ANSWERS_ROUND_n.md` 的链接给 GPT，让它据此产出/修订两份 md。
5. 重复，直到两份 md 的"仍未知"只剩必须上机/必须新训练才能解决的问题。

## 规则（双方都遵守）

- **数字必须有来源**：仓库相对路径（`03_field_logs/...`、`05_our_experiments/...`）或 `MANIFEST.csv`。
- **不得跨策略借证据**：v2-step ≠ HIMLoco。
- **区分仿真与实机**：`Isaac / MuJoCo / PhysX / REAL` 写清。
- **不存在的文件不要要**：先看 `AVAILABLE_DATA.md` 的"未包含"清单。
- **执行侧不猜**：回答不了的直接写 `UNKNOWN`，并给"需要什么测量/实验"。
- **GPT 不编**：读不到就写 `UNKNOWN`，并把它列进下一轮问题。

## 为什么复用同一个仓库

- 身份、合同、原始数据都在这里；另开仓库会让"哪份权重/哪个资产"再次分裂。
- GPT 已经建立上下文，换仓库要重读。
- 只在 `07_gpt_qa/` 下增量写，不覆盖已有证据。
